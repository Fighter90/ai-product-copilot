### REG-01 · Демо-учётки с ролью «Администратор» включены на проде

- **Роль / где:** безопасность, `/app/admin/users`
- **Факт:** на проде активны `admin@dashboardcamp.ru` (роль «Администратор») и
  `analyst@dashboardcamp.ru`; пароли демо-учёток распространялись в открытом виде (в т. ч. в чате).
  Любой, у кого есть пароль демо-админа, управляет пользователями, ключами AI и может очистить
  данные Метрики.
- **Ожидание:** по чек-листу production (`docs/deploy.md` §9) — `DEMO_USERS=0`; демо-доступ, если
  нужен, — только роль «Аналитик».
- **Что сделать:** сменить пароли демо-учёток («Сбросить пароль»), понизить демо-админа до
  аналитика или отключить; на сервере `DEMO_USERS=0`.

### REG-02 · `POST /api/hypotheses` и `POST /api/decisions` с неполным телом → 500

- **Роль / где:** аналитик и админ, API (`code/backend/src/routes/hypotheses.ts`,
  `routes/decisions.ts`)
- **Шаги:** `POST /api/hypotheses` с телом `{"title":"x"}`; `POST /api/decisions` с телом `{}`.
- **Факт:** `500 Internal Server Error` — `Cannot read properties of undefined (reading 'length')`.
- **Ожидание:** `400` с перечнем ошибок валидации (как у `/api/b2b`: `invalid body` + `issues`).
- **Примечание:** UI блокирует «Сохранить» у неполной формы, поэтому из интерфейса не
  воспроизводится, но любой клиент API (и будущие формы) роняет обработчик. Добавить Zod-схему
  на вход до обращения к полям.

### REG-03 · «Заявка ≠ оплата» нарушено в KPI: заказы считаются оплатами

- **Роль / где:** аналитик, «Обзор», «KPI и прогноз», «Отчёт»
- **Факт (14д):** кольцо «20 из 300», «Осталось до цели 280 · 20 оплачено из 300», «Темп оплат:
  1,4/день» — и тут же подсказка «Оплачено = B2C-оплаты + B2B… Сейчас: B2C — 0, B2B — 0»; карточка
  «Оплачено B2B 0». На 90д — «29 из 300». На «KPI и прогноз»: «Заказов (Метрика): 20 — Достижения
  цели-покупки из Метрики (это оплаты)». В срезе отчёта `gap = 294` при `b2cApplications = 6`,
  `b2bPaidTickets = 0` (300 − 6).
- **Причина:** основная цель автоопределена как «Ecommerce: покупка», и её достижения засчитываются
  в оплаты. Эта цель срабатывает при **создании заказа**, а не при оплате (см. ANA-19).
- **Ожидание:** прогресс к 300 и Gap — только по `b2c_payments` + B2B «Оплачено»; заказы — отдельной
  метрикой. Тексты подсказок и KPI должны говорить одно и то же.

### REG-04 · В SQLite прода только 17 дней истории — периоды 30д/90д/1г и отчёты молча неполные

- **Роль / где:** аналитик, все страницы «Аналитики», «Отчёт», «История»
- **Факт:** `/api/metrics/coverage` → `from 2026-10-13, days 17` для любого запроса с 01.07.
  `channel_stats` за 31.07–29.10 содержит 17 дат. Срез «Отчёт 30.09–29.10» (2729 визитов, 100 строк
  день×канал) фактически покрывает 13.10–29.10. «Качество данных» на «Обзоре» при 90д показывает
  только KPI-цель и UTM-покрытие — **о неполном периоде ни слова**. Прогноз на 90д берёт дедлайн от
  17-дневного окна («дедлайн 2 дек.»).
- **Ожидание:** (а) история за сезон загружена (`scripts/backfill-365.sh` порциями с учётом квоты
  Метрики); (б) если начало выбранного периода раньше `coverage.from` — предупреждение на страницах
  аналитики и в срезе («Данные есть с 13.10; период 30.09–29.10 покрыт на 17 из 30 дней»), а в
  DOCX/PDF — фактическое покрытие.

### REG-06 · Воронка pc-goals: конверсия шага > 100%, пропущенные шаги анкет

- **Роль / где:** аналитик, `/app/funnel-live` → «Заявки по ролям»
- **Факт (16–29.10):** C-level: «Открыл анкету 9 → Начал заполнять 7 → Заполнил часть 1 **0** →
  Заполнил часть 2 **0** → Отправил заявку **24 (342,9% от предыдущего шага)**». Спикер / волонтёр /
  партнёр: «Открыл анкету 0 → Начал заполнять 0 → Отправил заявку 8 / 29 / 3».
- **Причина (вероятно):** итог «Отправил заявку» берётся из цели `*_apply`, а промежуточные шаги — из
  целей шагов, которых в счётчике нет или они не срабатывают (`clevel_part1_submit` /
  `clevel_part2…`, `*_view`, `*_start` у остальных ролей).
- **Ожидание:** конверсия ограничена 100% или шаг без цели помечен «нет цели в счётчике» (как
  предупреждение для основной воронки); шаги без данных не обнуляют цепочку.

### REG-07 · Неработающий AI-провайдер остаётся в цепочке и в выборе на «Отчёте»

- **Роль / где:** админ `/app/admin/ai`; аналитик `/app/report` → «Провайдер»
- **Факт:** Anthropic — «Проверить соединение» → `HTTP 400 … credit balance is too low` (проверено
  29.10 вживую), при этом «Включён», есть в `/api/ai/available` и в списке «Провайдер» у аналитика.
  В «Авто» каждый вызов тратит попытку на него (до 2 ретраев), явный выбор — гарантированная ошибка.
- **Ожидание:** ops — пополнить баланс или выключить; продукт — помечать провайдера с неуспешной
  последней проверкой (⚠ в списке / исключать из `available`).

### REG-08 · Плитка «Заказов создано (B2B)» в отчёте показывает оплаченные B2B-билеты
