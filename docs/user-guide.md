# Руководство пользователя

> 🇷🇺 Русский · [🇬🇧 English](en/user-guide.md)

Руководство по личному кабинету ProductCamp Conversion Analytics (v3) — для команды трека
«Конверсии и лидген» (продакты, маркетологи, инженеры-волонтёры).

> ✅ **Статус: v3.0.0.** Личный кабинет с входом по сессиям и ролями **Администратор / Аналитик**,
> журналом действий (аудит). Мониторинг реального времени: **Live**, **Цели** (+деталь цели),
> **Воронка live**. Аналитика: Трафик, Поведение, Воронка, KPI, **Исследуй** (пресеты), Отчёт
> (DOCX/PDF + AI), История, B2B, **DataLens**. Админка: Пользователи, AI-провайдеры
> (OpenRouter/Anthropic/YandexGPT/GigaChat), Метрика, Интеграции, Аудит. RAG-ассистент по справке
> (правый нижний угол), раздел «Справка», интерфейс **ru/en**, тёмная/светлая тема.

Смежные документы: [быстрый старт](quickstart.md) · [деплой](deploy.md) · [runbook](runbook.md) ·
[архитектура](architecture.md) · [модель данных](data-model.md).

## 1. Что это и зачем

Инструмент отвечает на один вопрос: **откуда берутся платные билеты и как добрать до 300**.
Он не заменяет Яндекс.Метрику, а превращает её сырые цели в понятную картину: разбивку по каналам,
воронку «визит → заявка → оплата», приоритизированные гипотезы роста и Decision Log.

Два сквозных принципа:

- **Заявка ≠ оплата.** Достижение цели в Метрике (заявка) и фактическая оплата разделены везде в
  интерфейсе и в отчёте. Прогресс к KPI считается по оплатам.
- **Anti-hallucination.** Любое число на дашборде и в отчёте прослеживается до сырого ответа Метрики
  в таблице `raw_responses` (SQLite). Выдуманных цифр нет — это инвариант.

## 2. Вход и роли

Откройте `/login` и войдите с email и паролем (выдаёт администратор). Сессия живёт 7 дней
(`SESSION_DAYS`), выход — кнопка в шапке кабинета. Неудачные попытки ограничены (5 за 15 минут).
В профиле (меню пользователя) можно сменить **пароль**, **имя** и **язык интерфейса**.

| Роль              | Что доступно                                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Аналитик**      | весь кабинет: мониторинг, аналитика, отчёты, история, B2B, DataLens-экспорт, справка                              |
| **Администратор** | всё + «Администрирование»: пользователи, AI-провайдеры, Метрика, Интеграции, аудит; смена настроек; чистка данных |

Права проверяются на бэкенде: разделы администрирования и мутации настроек недоступны аналитику
(403), все действия попадают в журнал аудита. Пароль — минимум 10 символов.

## 3. Запуск (коротко)

Подробно — в [quickstart.md](quickstart.md); на сервер — [deploy.md](deploy.md):

```bash
git clone git@github.com:Fighter90/yandex-metrika-analyse-dashboard.git
cd yandex-metrika-analyse-dashboard
./setup.sh          # install → init → start
```

Локально: `http://localhost:5173` (API — `http://localhost:4000`, Swagger — `/docs`).
Первый администратор создаётся из `ADMIN_EMAIL`/`ADMIN_PASSWORD` в `.env` при пустой таблице
пользователей. Без OAuth-токена аналитика поднимется на демо-данных (`pnpm seed`).

## 4. Кабинет: интерфейс

- **Сайдбар** (сворачиваемый) сгруппирован по разделам: «Монитор», «Аналитика», «Работа»,
  «Администрирование» (последний — только у админа). На мобиле — нижние табы + «Ещё».
- **Топбар**: глобальные фильтры, переключатель **темы** (🌙/☀️), переключатель **языка RU/EN**,
  колокольчик **уведомлений** (события DataLens и запросы аналитиков), меню пользователя.
- **Футер**: версия продукта (из корневого `package.json`) + короткий git-sha сборки.
- **RAG-ассистент** — плавающая кнопка в правом нижнем углу (см. §10).
- **Справка** — раздел «Справка» в сайдбаре или `/help` (см. §10).

Тема и язык сохраняются в браузере (localStorage); язык также пишется в профиль пользователя.

## 5. Страницы кабинета

### Монитор (реальное время — напрямую из Яндекс.Метрики, без кэша)

| Страница         | URL                | Что показывает                                                                                                                                                                             |
| ---------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Обзор**        | `/app`             | KPI-стрип, визиты/заявки по дням, микс каналов, слабые места — по данным SQLite (история по дням)                                                                                          |
| **Live**         | `/app/live`        | реальное время: визиты/цели за сегодня, события ProductCamp, динамика по часам                                                                                                             |
| **Цели**         | `/app/goals`       | все цели счётчика: статус (live/sleeping/dead), достижения за 14/90 дней, дубликаты целей; деталь — `/app/goals/:id`                                                                       |
| **Воронка live** | `/app/funnel-live` | воронка PC-событий: увидел билеты → клик CTA → открыл регистрацию → корзина → оставил контакты; билеты по типам (standard/optimal/max) и заявки по ролям (волонтёр/спикер/C-level/партнёр) |

### Аналитика (SQLite, история по дням, `npm run sync`)

| Страница      | URL                    | Что показывает                                                                                                                                                         |
| ------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Трафик**    | `/app/traffic`         | бар каналов, визиты vs заявки, таблица каналов с CR, UTM-разбивка, insights                                                                                            |
| **Поведение** | `/app/behavior`        | страницы входа/выхода: графики отказов/CR + таблицы, рекомендации                                                                                                      |
| **Воронка**   | `/app/funnel`          | «заявка ≠ оплата»: Визиты → Заявки B2C → B2B pipeline → Оплачено B2B; воронка по каналам, анализ потерь                                                                |
| **KPI**       | `/app/kpi`             | прогресс-ринг к 300 оплаченным билетам (B2B paid + цели-покупки), «Что если»-симулятор, рекомендации                                                                   |
| **Исследуй**  | `/app/explore/:preset` | быстрые срезы Reporting API по пресетам: источники, поисковые системы, UTM, страницы, устройства, браузеры, гео, рефереры, дни, часы — таблица + график + CSV-выгрузка |

### Работа

| Страница     | URL             | Что показывает                                                                                      |
| ------------ | --------------- | --------------------------------------------------------------------------------------------------- |
| **Отчёт**    | `/app/report`   | снапшот периода, полный отчёт на экране, AI-гипотезы и AI Decision Log, AI-анализ, экспорт DOCX/PDF |
| **История**  | `/app/history`  | сохранённые снапшоты; «Просмотреть» открывает отчёт без перегенерации                               |
| **B2B**      | `/app/b2b`      | kanban-пайплайн 4 этапов (lead → negotiation → invoiced → paid), полная таблица сделок              |
| **DataLens** | `/app/datalens` | описание 5 CSV-датасетов для Яндекс DataLens, скачивание за период, запрос на подключение (см. §9)  |

Старые до-v3 URL (`/traffic`, `/report`, `/settings`, …) редиректят в соответствующие разделы
`/app/…`.

### Фильтры (топбар аналитики)

- Пресеты периода **7д / 14д / 30д / 90д / 1г** и кастомный период (от → до, максимум 365 дней).
- **Сегмент** B2C / B2C+B2B / B2B — фильтрует каналы и UTM.
- **Тестовый трафик** (на live-страницах) — включение/исключение помеченного тестового трафика.
- На Live-страницах фильтры относятся к периоду запросов Reporting API, а не к SQLite.

## 6. Администрирование (только роль «Администратор»)

### Пользователи (`/app/admin/users`)

Список пользователей: создание (email, имя, роль; кнопка «Создать» возвращает **одноразовый пароль**
— покажется один раз), смена роли, блокировка (`is_active`), «Сбросить пароль» (новый одноразовый
пароль). Система не даст понизить/заблокировать последнего активного админа.

### AI-провайдеры (`/app/admin/ai`)

Четыре провайдера: **OpenRouter, Anthropic, YandexGPT, GigaChat**. Для каждого: включение,
**приоритет** в цепочке, модель (выбор из списка), секретный ключ и доп. поля (`folderId` у
YandexGPT, `scope` у GigaChat). Кнопка «Проверить» делает тестовый запрос и показывает результат.
Ключи шифруются **AES-256-GCM** мастер-ключом `APP_SECRET` и в БД хранятся только шифротекстом;
на экране ключ всегда маскирован. Статистика вызовов за 30 дней — на той же странице (`ai_usage`).
AI используется: отчёт (анализ/гипотезы/Decision Log) и ассистент по справке. Провайдеры
обходятся по приоритету — сбой одного автоматически переключает на следующий.

### Метрика (`/app/admin/metrika`)

Runtime-настройки интеграции: OAuth-токен, Client ID/Secret, `COUNTER_ID`, `GOAL_ID`
(`0` = авто-определение цели-покупки), `ORDER_GOAL_ID`, цель KPI. Секреты маскируются; пустое поле
= «не менять». Изменения применяются **без рестарта** (пересборка клиента Метрики). Здесь же —
«Обновить данные из Метрики» (синхронизация с прогрессом) и очистка данных Метрики.

**Как получить OAuth-токен:** создайте приложение на oauth.yandex.ru с доступом
`metrika:read` (и `metrika:write` — для создания целей из админки), откройте ссылку
авторизации из настроек, скопируйте `access_token` из адресной строки после редиректа
и вставьте в поле «OAuth-токен».

**Создание и архивация целей.** В разделе «Админ → Метрика» цели создаются напрямую через
Management API: тип (URL / действие / шаг / количество …), название, условия
(exact / contains / starts / regex). Тип условия `js` Management API не принимает —
JS-события оформляются целью типа «действие» с URL-условием. Созданная цель появляется
в кабинете после следующего синка (или ручного «Синк»).

**Фильтр служебного трафика.** По умолчанию роботы и локальные визиты исключены и из синка,
и из live-страниц. Переменная `INCLUDE_TEST_TRAFFIC=1` возвращает «как есть» (для отладки).

**Синк по расписанию.** На сервере синк выполняется каждые 3 часа (systemd-таймер
`pca-sync.timer`); ручной запуск — кнопкой в админке или `systemctl start pca-sync.service`.

### Интеграции (`/app/admin/integrations`)

Яндекс DataLens: webhook-токен приёмника, последние события (коды подтверждения и уведомления),
ссылки на дашборды (`DATALENS_LINKS`). Webhook URL публичный, но защищён токеном из URL.

### Аудит (`/app/admin/audit`)

Журнал действий: входы/выходы (включая неуспешные), создание/изменение пользователей, смена
паролей, экспорты DataLens, запросы на подключение — время, пользователь, действие, объект, детали.

## 7. B2B-пайплайн (`/app/b2b`)

Ручной ввод B2B-сделок (Метрика B2B не покрывает):

- **Kanban из 4 этапов**: lead → negotiation → invoiced → paid.
- Форма добавления (компания / билеты / этап); полная редактируемая таблица — рядом.
- Оплаченные (`paid`) билеты засчитываются в KPI 300 на страницах «Воронка» и «KPI».
- Хранение — таблица `b2b_manual`; CRUD через `POST/PATCH/DELETE /api/b2b`.

## 8. Генерация отчётов (DOCX/PDF + AI)

На странице **Отчёт** (`/app/report`):

1. Выберите период и нажмите **«Сформировать срез данных»** — соберётся и сохранится неизменяемый
   `ReportSnapshot`, отчёт откроется прямо на экране (включая AI-гипотезы и AI Decision Log).
2. (Опционально) **«Сгенерировать AI-анализ»** — идёт через цепочку AI-провайдеров из чисел
   снапшота (6 секций: Итог · Каналы/UTM/Аудитория · Страницы/Воронка · Риски/Рекомендации ·
   Гипотезы/Дорожная карта · Итоговый вывод). Если провайдеры не настроены — администратор включает
   их в «Администрирование → AI-провайдеры»; отчёт собирается и без AI-секции.
3. **Export DOCX / Export PDF** — скачивание (PDF требует Chrome: авто-поиск или
   `PUPPETEER_EXECUTABLE_PATH`; DOCX — без зависимостей).
4. **Перестроить отчёт** — пересборка снапшота с текущими фильтрами.

Отчёт оформлен по ГОСТ Р 7.32-2017 (титульная страница, содержание, Times New Roman 14pt),
графики встроены картинками, у каждого — блок 🟢/🔴. Детерминизм: один `snapshotId` → один и тот же
контент в DOCX, PDF и на экране; в render-пути нет `Date.now()` и LLM — нарратив и PNG генерируются
один раз и хранятся в снапшоте.

## 9. DataLens (`/app/datalens`)

### Как работает система

Яндекс.Метрика → наш синк (SQLite, срезы по дням, каждые 3 часа) → два канала в DataLens:

1. **CSV-датасеты** из кабинета (подключение «Файлы» в DataLens);
2. **Нативный коннектор Метрики** (live-данные, автообновление).

### Настройка (пошагово)

1. Войдите на [datalens.ru](https://datalens.ru) под аккаунтом владельца.
2. Создайте воркбук «ProductCamp Analytics» (или откройте созданный: `t2q8gxrkkwvwc` —
   воркбук и подключение Метрики уже созданы через Public API).
3. Скачайте CSV со страницы `/app/datalens` (5 датасетов, период до 365 дней).
4. Подключения → **Файлы** → загрузите CSV → проверьте типы колонок (даты/числа).
5. Соберите чарты: «Визиты и заказы по дням» (line), «Каналы» (bar), «Структура» (donut),
   «Воронка заявка→заказ», «B2B-пайплайн» — и соберите их в дашборд.
6. Вебхук-алерты чартов: URL из «Админ → Интеграции» (токен генерируется там же).

### Автосоздание через API

`scripts/push-datalens.mjs` создаёт воркбук, подключение Метрики и датасет через Public API
(нужны IAM-токен и ID организации — см. шапку скрипта).

### Сверка данных

CSV-выгрузка и страницы кабинета используют один источник (`channel_stats` и др.) —
суммы совпадают 1-в-1; при расхождении проверьте период и свежесть синка.

Страница **DataLens** (`/app/datalens`) — мост в Яндекс DataLens через **Files-подключение**:

| Датасет            | Содержимое (по дням, если не сказано иное)                              |
| ------------------ | ----------------------------------------------------------------------- |
| `channels_daily`   | каналы: визиты, посетители, отказы, длительность, заказы (цель KPI), CR |
| `utm_daily`        | utm_source / medium / campaign: визиты, посетители, заказы              |
| `pages_daily`      | страницы входа: визиты, посетители, отказы, заказы                      |
| `geo_device_daily` | страна + устройство: визиты, посетители, заказы                         |
| `b2b_deals`        | B2B-сделки: компания, билеты, этап, сумма, даты                         |

Как использовать: скачайте CSV за период (или заберите URL экспорта) → в DataLens создайте
подключение **Files** и загрузите датасет; заголовки колонок локализованы (ru/en — параметр `lang`).
Формат: UTF-8 с BOM, разделитель — запятая, RFC 4180. Обратный канал — **webhook-приёмник**:
DataLens присылает код подтверждения и алерты на `POST /api/integrations/datalens/webhook/:token`;
коды и события видны админу в «Интеграциях» и в колокольчике. Аналитик может нажать
«Запросить подключение» — админам уйдёт уведомление.

Каждый экспорт фиксируется в аудите (`datalens.export`).

## 10. Справка и RAG-ассистент

- **Раздел «Справка»** (`/help`) — статьи из `docs/help/ru` (или `docs/help/en` для английского):
  описание страниц, целей, воронки, интеграций; поиск по заголовкам.
- **Ассистент** — плавающая кнопка (правый нижний угол) на любой странице. Отвечает **только по
  текстам справки**: вопрос → поиск релевантных чанков статей → ответ модели с ссылками на статьи.
  Работает через настроенных AI-провайдеров; если они не настроены — сообщение администратору.
  Вопросы не записываются в БД, фиксироваться может только техническая статистика вызова (`ai_usage`).

## 11. Язык и тема

- **Язык RU/EN** — переключатель в топбаре кабинета; выбор сохраняется в браузере и в профиле
  (следующий вход откроет кабинет на выбранном языке). Справка и ассистент отвечают на языке UI.
- **Тема** — тёмная/светлая (переключатель 🌙/☀️ в топбаре); применяется до первой отрисовки,
  «мигания» нет. Сохраняется в браузере.

## 12. Источники данных

### Яндекс.Метрика (Stat API — синхронизация в SQLite)

| Запрос                         | Что приносит                                        |
| ------------------------------ | --------------------------------------------------- |
| `traffic-by-source`            | визиты, пользователи, отказы, заявки, CR по каналам |
| `utm-breakdown`                | разбивка по UTM: source / medium / campaign         |
| `geo-device-breakdown`         | страна + тип устройства                             |
| `page-behavior` (startURL)     | страницы входа: визиты, отказы, заявки              |
| `exit-page-behavior` (exitURL) | страницы выхода (на живых данных часто пусто)       |

`attribution=lastsign`, проценты нормализуются в долю 0–1, история — по дням (повторный sync
дополняет, не затирая).

### Live-режим (Reporting API напрямую)

Страницы Live / Цели / Воронка live / Исследуй запрашивают Reporting API в реальном времени
с токеном из настроек администратора и **не пишут в SQLite**.

### Ручной ввод (B2B)

`b2b_manual`: company, tickets, stage (lead/negotiation/invoiced/paid), amountRub, contactEmail,
notes, dateAdded, datePaid. Модель — [data-model.md](data-model.md).

## 13. Устранение проблем

- **Не пускает в кабинет:** проверьте email/пароль; 5 неудач подряд → подождите 15 минут. Пароль
  сбрасывает админ («Пользователи» → «Сбросить пароль»).
- **Не видно раздела «Администрирование»:** нужна роль `admin` — просите существующего админа
  повысить вашу учётную запись.
- **«Нет настроенных AI-провайдеров»:** админу — включить провайдера в «Администрирование →
  AI-провайдеры» (ключ + модель + «Проверить»).
- **Live-страницы пустые:** админу проверить токен и `COUNTER_ID` в «Метрике»; live требует живого
  токена с правом чтения отчётов.
- **Нет данных из Метрики (аналитика):** нажмите «Обновить данные» в «Администрирование → Метрика»
  или запустите `npm run sync`; смотрите логи backend.
- **PDF не экспортируется:** задайте `PUPPETEER_EXECUTABLE_PATH` на путь к Chrome (см. runbook).
- **Смена цели/исправление единиц:** требует чистой БД (`rm data/productcamp.sqlite*`).

## 15. Принципы, о которых стоит помнить

- Любая цифра прослеживается до `raw_responses` — если не прослеживается, это баг.
- Заявка ≠ оплата: эти метрики не суммируются; прогресс к KPI — по оплатам.
- Секреты (токены, ключи AI) вводятся только в админке или `.env`; в интерфейсе они всегда маски.
- Действия админов и экспорты фиксируются в аудите — журнал не редактируется.
- Новые зависимости вне зафиксированного стека — только через ADR в `docs/decisions/`.
