# Модель распределения решений ИИ↔PM (матрица автономии)

> 🇷🇺 Русский. Методология разделения ответственности между ИИ и продуктом (PM) в Decision Log.
> Реализация: `code/shared/src/types/decision-autonomy.ts` (таксономия, матрица, оценка),
> `code/backend/src/routes/decisions.ts` (API), `code/frontend/src/pages/app/Decisions.tsx`
> (бейджи + блок «Матрица автономии»). Вечная спека:
> [`openspec/specs/decision-autonomy/spec.md`](../openspec/specs/decision-autonomy/spec.md).
> Источник требования: ANA-127 п.7 (flow «гипотезы→решения» после AI-анализа) и
> [`openspec/changes/archive/decision-autonomy-model/proposal.md`](../openspec/changes/archive/decision-autonomy-model/proposal.md).
> Любое изменение матрицы или уровней фиксируется здесь с обоснованием.

## 1. Зачем нужна модель

ANA-128 научил систему писать AI-черновики решений в Decision Log автоматически после
AI-анализа. Без явной модели распределения возникает развилка: либо каждое действие ИИ
требует подтверждения PM (команда тонет в подтверждениях), либо ИИ действует без надзора
(риск необратимых или публичных последствий). Модель отвечает на один вопрос:

> **До какого уровня автономии ИИ может доводить решение каждого типа — и когда решение
> возвращается человеку.**

Модель — **только классификация и отображение**: ни одно действие уровня `A2` не исполняется
автоматически без PM. Render-путь DOCX/PDF-отчёта модель не изменяет.

## 2. Уровни автономии (A0–A2)

| Уровень | Название                | Смысл                                                         |
| ------- | ----------------------- | ------------------------------------------------------------- |
| `A0`    | ИИ только предлагает    | любое применение решения — после подтверждения PM             |
| `A1`    | ИИ действует по шаблону | ИИ исполняет по фиксированному шаблону, PM ревьюит постфактум |
| `A2`    | ИИ автономно в лимитах  | ИИ действует сам в заранее заданных лимитах                   |

Уровни упорядочены (`A0 < A1 < A2`) — ранги живут в `AUTONOMY_LEVEL_RANK` и являются
единственным источником сравнений.

## 3. Таксономия типов решений и матрица

Каждое AI-решение (`decisions.source = 'ai'`) относится к одному из **8 типов**:

| Тип                 | Макс. автономия | Почему                                                                  |
| ------------------- | --------------- | ----------------------------------------------------------------------- |
| `data-analysis`     | `A2`            | обратимо: пересчитать/переспросить можно без последствий                |
| `hypothesis-draft`  | `A1`            | кодифицирует фактическое поведение ANA-128: черновик + постфактум-ревью |
| `experiment-launch` | `A0`            | тратит трафик и время команды — запуск решает PM                        |
| `pricing`           | `A0`            | влияет на деньги и публичное предложение                                |
| `budget`            | `A0`            | необратимые траты                                                       |
| `public-comms`      | `A0`            | публичные коммуникации нельзя «откатить»                                |
| `strategic`         | `A0`            | стратегические развилки — зона человека                                 |
| `legal`             | `A0`            | юридические решения ИИ не делегируются никогда                          |

Логика разбиения: чем **обратимее** и **внутреннее** результат, тем выше допустимая
автономия; деньги, публичность, необратимость и юриспруденция остаются на уровне `A0`.

Матрица — **статическая константа в коде** (`AUTONOMY_MATRIX` в `@pca/shared`), не в БД.
Обоснование: контракт меняется только осознанным релизом (code review + ADR), не правкой
строки в таблице; так он остаётся воспроизводимым и прослеживаемым (anti-hallucination).

## 4. Правила эскалации к PM

- **Требуемый уровень — константа `A1`** в MVP: каждое AI-решение исполняется ИИ на одном
  уровне «черновик + постфактум-ревью» (поведение ANA-128). Модель не выводит требуемый
  уровень из содержимого решения — это осознанное упрощение MVP.
- **Эскалация** (`escalation.required = true`) — тогда и только тогда, когда требуемый
  уровень выше максимального допустимого для типа (`maxAutonomy(тип) < 'A1'`) — либо тип
  не определён.
- **Причина** — машинно-читаемый код: `'autonomy-exceeded'` (тип с максимумом `A0`) или
  `'unclassified-type'` (тип не распознан). API возвращает сырой код; UI маппит его в
  локализованный текст (ru и en).
- **Консервативная трактовка:** неклассифицируемое AI-решение (`decision_type = NULL`)
  трактуется как `strategic` — максимум `A0`, поэтому эскалируется с причиной
  `'unclassified-type'`. Принцип: сомнение — в пользу человека.
- `data-analysis` (`A2`) и `hypothesis-draft` (`A1`) не эскалируются: запас `data-analysis`
  до `A2` — задел на будущее автоисполнение (в MVP не исполняется).

## 5. Legacy-бэкфилл

Миграция `020_decision_type.sql` бэкфилл-ит существующие AI-строки
(`source = 'ai'`, `decision_type IS NULL`) значением `hypothesis-draft`: на момент миграции
все они созданы ai-autopopulate (ANA-128) как черновики проверки гипотез. Поэтому при
деплое ни одна legacy-строка не порождает бейдж «требует PM-эскалации». `NULL` после
миграции допустим только у неклассифицируемых строк и оценивается консервативно (§4).

## 6. Как это видно пользователю

- `/app/decisions`: карточка AI-решения показывает бейдж типа, бейдж уровня автономии
  (`A0`–`A2`, подсказка = смысл уровня) и — при эскалации — бейдж
  «⚠️ Требует PM-эскалации» с локализованной причиной (title/tooltip). Manual-решения
  бейджев автономии не имеют: их принял человек.
- Там же — блок **«Матрица автономии ИИ»**: таблица «тип → макс. уровень → правило
  эскалации» из `GET /api/decisions/autonomy-matrix` (те же константы, что и в оценке, —
  расхождение UI и API невозможно). Таблица обёрнута в `overflow-x-auto` — на мобильном
  390px страница не скроллится по горизонтали.
- `decision_type` не редактируется ни через API, ни через UI (исправление классификации —
  правкой классификатора/матрицы в коде, релизом).

## 7. Связь с методологией гипотез

Decision Log — финал цикла гипотезы ([methodology-hypotheses.md](methodology-hypotheses.md)).
Модель автономии не меняет цикл: она лишь фиксирует, **кто** доводит решение каждого типа
до какого уровня и когда человек обязан вернуться в цикл. «Заявка ≠ оплата» и
anti-hallucination действуют как раньше: каждое число в решении прослеживается до
`raw_responses` через снапшот.
