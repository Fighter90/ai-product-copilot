# Руководство администратора

> 🇷🇺 Русский · [🇬🇧 English](en/admin-guide.md). Версия продукта v3.1.0 · стенд
> <https://dashboardcamp.ru>. Постраничный разбор с кнопками и скриншотами — во встроенной
> справке кабинета (`/help`, раздел «Админ»); здесь — самодостаточный регламент администратора.

Администратор видит всё, что видит аналитик ([user-guide.md](user-guide.md)), плюс раздел
«Администрирование» в сайдбаре. Права проверяются на сервере: `/api/admin/**`, `/api/users`,
изменение настроек, AI-провайдеров и удаление данных доступны только роли «Администратор»,
остальным — HTTP 403 `ADMIN_ONLY`.

## 1. Первичная настройка (чек-лист)

1. **Сервер.** В `.env` задан `APP_SECRET` (мастер-ключ шифрования секретов в БД), `COOKIE_SECURE=1`
   за HTTPS, `DEMO_USERS=0` — см. [deploy.md](deploy.md).
2. **Первый вход.** Загрузочный администратор создаётся при старте из `ADMIN_EMAIL` /
   `ADMIN_PASSWORD`, пока таблица `users` пуста. После входа заведите второго администратора и
   уберите пароль из `.env`.
3. **Метрика и данные** — счётчик, OAuth-токен, «Сохранить» → «Обновить данные из Метрики».
4. **AI-провайдеры** — хотя бы один провайдер с ключом: «Сохранить» → «Проверить соединение» →
   «Включён».
5. **Пользователи** — завести аналитиков, передать временные пароли защищённым каналом.
6. **Интеграции** — по необходимости DataLens: подключение API, URL вебхука, ссылки на дашборды.
7. **Аудит** — убедиться, что все шаги записались в журнал.

## 2. Пользователи и роли (`/app/admin/users`)

| Роль          | Может                                                                                       |
| ------------- | ------------------------------------------------------------------------------------------- |
| Аналитик      | Обзор, Live, Цели, Воронки, Трафик, Поведение, KPI, Исследуй, Отчёт, История, B2B, DataLens |
| Администратор | всё перечисленное + Пользователи, AI-провайдеры, Метрика и данные, Интеграции, Аудит        |

- **Создать пользователя:** «Добавить пользователя» → имя, email, роль → «Сохранить». Временный
  пароль показывается **один раз** — скопируйте и передайте человеку защищённым каналом.
- **Сбросить пароль:** «Сбросить пароль» выпускает новый временный пароль и завершает все сессии
  пользователя. Отдельной формы «забыли пароль» нет — сброс делает администратор.
- **Сменить роль:** список «Роль» в строке пользователя, применяется сразу.
- **Отключить:** «Отключить» блокирует вход и немедленно завершает все сессии; запись и история в
  аудите сохраняются (удаления пользователей нет).
- **Защита последнего администратора:** понизить или отключить единственного активного админа
  нельзя (HTTP 409). Держите минимум двух администраторов.
- **Безопасность входа:** пароли — scrypt; сессия — cookie `pca_session` (HttpOnly), в БД только
  sha256-хэш токена; срок — `SESSION_DAYS` (7 дней); 5 неудачных входов за 15 минут с пары
  ip+email → HTTP 429.

## 3. AI-провайдеры и ключи (`/app/admin/ai`)

AI нужен для AI-анализа отчёта, AI-гипотез с Decision Log и RAG-ассистента справки. Остальное
(дашборды, воронки, DOCX/PDF) работает без AI.

| Провайдер  | Что нужно                                           | Где взять                                                                                                                | Модель по умолчанию           |
| ---------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------- |
| OpenRouter | API key (`sk-or-…`)                                 | openrouter.ai/keys → Create Key; нужен баланс Credits                                                                    | `anthropic/claude-sonnet-4.5` |
| Anthropic  | API key (`sk-ant-…`)                                | console.anthropic.com → Settings → API Keys; нужен баланс                                                                | `claude-sonnet-4-6`           |
| YandexGPT  | API-ключ сервисного аккаунта + ID каталога (`b1g…`) | Yandex Cloud / AI Studio: сервисный аккаунт с ролью `ai.languageModels.user` → API-ключ (`yc.ai.languageModels.execute`) | `yandexgpt/latest`            |
| GigaChat   | Authorization Key + scope                           | developers.sber.ru → проект GigaChat API; scope `GIGACHAT_API_PERS` / `_B2B` / `_CORP`                                   | `GigaChat-2-Pro`              |

**Порядок:** вставить ключ → доп. поля (folder ID / scope) → «Сохранить» → «Проверить соединение»
→ галочка «Включён».

- **Цепочка по приоритету:** берутся только включённые провайдеры с сохранённым ключом; меньше
  приоритет — раньше (по умолчанию 10 / 20 / 30 / 40). Временные ошибки (429, 5xx, сеть) — до 2
  повторов, затем запрос уходит следующему провайдеру.
- **Хранение:** ключи шифруются AES-256-GCM мастер-ключом `APP_SECRET`; в UI и API — только маска
  `••••abcd`. Пустое поле ключа при сохранении = «оставить текущий».
- **Смена `APP_SECRET`** делает сохранённые ключи нерасшифровываемыми — введите их заново.
- **GigaChat и TLS:** серверы Сбера подписаны Russian Trusted Root CA (Минцифры). На сервере нужен
  `NODE_EXTRA_CA_CERTS` с PEM корневого и промежуточного сертификатов — `deploy/deploy.sh` ставит
  их и прописывает переменную сам. Симптом отсутствия: «gigachat: fetch failed» /
  `SELF_SIGNED_CERT_IN_CHAIN`.
- **`.env`-ключи** (`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `YANDEX_AI_API_KEY` +
  `YANDEX_AI_FOLDER_ID`, `GIGACHAT_AUTH_KEY` + `GIGACHAT_SCOPE`) подставляются один раз при пустой
  таблице провайдеров; дальше источник истины — эта страница.
- **Статистика:** блок «Использование за 30 дней» — вызовы и ошибки по провайдерам (`ai_usage`;
  содержимое запросов не хранится).

Подробно по каждому провайдеру и ошибкам — статья справки «Ключи LLM-провайдеров» (`/help`).

## 4. Яндекс.Метрика и данные (`/app/admin/metrika`)

### Подключение

Возле каждого поля — метка источника: `db` (задано в админке), `env` (из `.env`), `unset`.
«Сохранить» применяется **без перезапуска** — клиент Метрики пересобирается.

| Поле                | Ключ                                        | Что вводить                                                                      |
| ------------------- | ------------------------------------------- | -------------------------------------------------------------------------------- |
| Счётчик Метрики     | `COUNTER_ID`                                | номер счётчика                                                                   |
| OAuth-токен         | `YANDEX_OAUTH_TOKEN`                        | `metrika:read` (+ `metrika:write` для управления целями); хранится зашифрованным |
| Client ID / secret  | `YANDEX_CLIENT_ID` / `YANDEX_CLIENT_SECRET` | OAuth-приложение для `pnpm auth`; секрет — зашифрованным                         |
| Цель «Заказ»        | `ORDER_GOAL_ID`                             | ID цели заказа для live-страниц                                                  |
| Цель KPI для отчёта | `GOAL_ID`                                   | `0` — автоопределение цели-покупки при синке                                     |
| Цель по оплатам     | `KPI_TARGET`                                | целевое число оплат (300)                                                        |

Секретные поля показывают маску; не трогайте её, чтобы оставить значение, или сотрите и вставьте
новое.

### OAuth-токен

1. На oauth.yandex.ru создайте приложение с доступами `metrika:read` и `metrika:write`.
2. Выпустите токен от аккаунта с доступом к счётчику — вручную или командой `pnpm auth` (запишет
   `YANDEX_OAUTH_TOKEN` в `.env`; подробности — [README.md](../README.md)).
3. Вставьте токен в поле «OAuth-токен» → «Сохранить» → проверьте Live-страницу.

### Синхронизация

- «Обновить данные из Метрики» грузит агрегаты за период глобального фильтра (по умолчанию 14
  дней, до 365): каналы, UTM, гео/устройства, страницы входа и выхода, цели.
- На сервере синк идёт автоматически каждые 3 часа (`pca-sync.timer`). Ручной синк нужен после
  смены счётчика/токена, создания целей и для загрузки длинной истории.
- Роботы и тестовые сессии (`file:`) исключаются; `INCLUDE_TEST_TRAFFIC=1` отключает фильтр.
- **Опасная зона:** «Очистить данные Метрики» (подтверждение словом `УДАЛИТЬ`) удаляет
  `raw_responses` и производные таблицы; отчёты-срезы, гипотезы, B2B, пользователи и настройки
  сохраняются. Сразу запустите синк. В аудите — `data.clear_metrika`.

### Цели Метрики

Управление целями — через Management API, нужен токен с `metrika:write`. Операции доступны
администратору как API-эндпоинты в рамках сессии кабинета:

| Операция     | Запрос                                       |
| ------------ | -------------------------------------------- |
| Создать      | `POST /api/admin/metrika/goals`              |
| Архивировать | `POST /api/admin/metrika/goals/<ID>/archive` |
| Восстановить | `POST /api/admin/metrika/goals/<ID>/restore` |

Типы условий — `exact`, `contains`, `starts`, `regex` (тип `js` Метрика не принимает: JS-событие —
цель `action` с условием по идентификатору события). Новая цель появится после следующего синка.
Ошибки: 409 — Метрика не настроена; 401 — токен истёк; 403 — нет доступа к счётчику или права
`metrika:write`; 429 — лимит API. Аудит: `metrika.goal_created / goal_archived / goal_restored`.

## 5. Интеграции: Яндекс DataLens (`/app/admin/integrations`)

### Подключение к DataLens Public API

| Поле        | Ключ                   | Где взять                                                                                                    |
| ----------- | ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| Org ID      | `DATALENS_ORG_ID`      | datalens.ru → настройки организации → ID организации                                                         |
| Workbook ID | `DATALENS_WORKBOOK_ID` | из адреса `datalens.ru/workbooks/<ID>`                                                                       |
| IAM-токен   | `DATALENS_IAM_TOKEN`   | `yc iam create-token` (живёт ≤ 12 ч) или токен сервисного аккаунта с ролью в DataLens; хранится шифротекстом |

Настройки хранятся в БД (`app_settings`), не в `.env`, и применяются сразу. «Проверить
подключение» обращается к DataLens API и пишет `datalens.check` в аудит. Ошибки: «Не заполнено: …»;
401 — IAM-токен истёк; 403 — неверный Org ID или нет роли; 404 — нет воркбука; таймаут 15 с — сеть.

CSV-датасеты (каналы, UTM, страницы, гео+устройства, B2B-сделки) подключаются в DataLens вручную
через Files-подключение; исходники — `GET /api/integrations/datalens/export/:id`. Воркбук и
подключение Метрики можно создать скриптом `scripts/push-datalens.mjs`
(`DATALENS_IAM_TOKEN`, `DATALENS_ORG_ID` в окружении процесса).

### Вебхук и токен приёмника

- Адрес вида `https://<домен>/api/integrations/datalens/webhook/<токен>`; токен в адресе
  (`DATALENS_WEBHOOK_TOKEN`, хранится зашифрованным) — единственная защита приёмника.
- «Выпустить новый URL» генерирует новый токен, **старый адрес сразу перестаёт работать**; аудит —
  `datalens.token_rotated`.
- В DataLens: Настройки → Уведомления → Вебхуки → «Добавить вебхук» → URL → «Получить код» → код
  появится в карточке «Последний код подтверждения» и в колокольчике.
- События хранятся в `datalens_events` (последние 500).

### Ссылки на дашборды и запросы аналитиков

- «Ссылки на дашборды DataLens» (`DATALENS_LINKS`, по одной в строке, `http(s)://`) видны всем на
  странице «DataLens».
- Аналитик может «Попросить администратора подключить» — уведомление админам и запись
  `datalens.request` (не чаще 3 раз в час на пользователя).

## 6. Журнал действий (`/app/admin/audit`)

Ответ на вопрос «кто, когда и что изменил». Последние 1000 записей, поиск, сортировка, экспорт
CSV. Секреты в журнал не пишутся.

| Группа       | Действия                                                                          |
| ------------ | --------------------------------------------------------------------------------- |
| Вход         | `auth.login`, `auth.login_failed`, `auth.logout`, `auth.password_changed`         |
| Пользователи | `users.create`, `users.update`, `users.reset_password`                            |
| Настройки    | `settings.update` (список ключей), `data.clear_metrika`                           |
| AI           | `ai.provider_update`, `ai.provider_test`                                          |
| Метрика      | `metrika.goal_created`, `metrika.goal_archived`, `metrika.goal_restored`          |
| DataLens     | `datalens.export`, `datalens.request`, `datalens.check`, `datalens.token_rotated` |

Типовые расследования: пропали данные — `data.clear_metrika`; кто сменил токен — `settings.update`
с `YANDEX_OAUTH_TOKEN`; подбор пароля — серия `auth.login_failed` по одному email.

## 7. Бэкапы, мониторинг, эксплуатация

| Что                  | Как                                                                                                           | Где подробно                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| Ночной бэкап         | `pca-backup.timer` (04:30) → `deploy/backup.sh`: `sqlite3 .backup` → gzip → `/opt/pca/backups/`, 14 копий     | [deploy/DEPLOY.md](../deploy/DEPLOY.md), § 5   |
| Офсайт-копия         | `scripts/pull-backup.sh` забирает свежий бэкап на машину владельца (30 копий)                                 | шапка скрипта                                  |
| Восстановление       | остановить `pca-api` → подменить базу, удалить `-wal`/`-shm` → старт → `/api/health`                          | [deploy/DEPLOY.md](../deploy/DEPLOY.md), § 5.2 |
| Мониторинг           | `pca-monitor.timer` (каждые 5 мин): 3 неудачи `/api/health` подряд → рестарт API; диск > 85% → предупреждение | [deploy/DEPLOY.md](../deploy/DEPLOY.md), § 5   |
| Деплой и обновление  | `deploy/deploy.sh`; вручную — `git pull` → build → миграции → `systemctl restart`                             | [deploy.md](deploy.md)                         |
| Запуск и траблшутинг | локальный запуск, PDF, частые ошибки                                                                          | [runbook.md](runbook.md)                       |

Секреты (`.env`) в бэкапы БД не попадают — храните копию `.env` отдельно и защищённо. Без того же
`APP_SECRET` зашифрованные в БД токены и ключи после восстановления не расшифруются.

## 8. Рутина и частые проблемы

- **Ежедневно:** колокольчик (запросы аналитиков, события DataLens); Live — данные идут.
- **Еженедельно:** «Использование за 30 дней» у AI; `auth.login_failed` в аудите; актуальность
  списка пользователей; свежесть бэкапов.
- **По событию:** истёк токен Метрики или IAM-токен DataLens — выпустить новый; ушёл сотрудник —
  «Отключить».

| Симптом                                       | Решение                                                          |
| --------------------------------------------- | ---------------------------------------------------------------- |
| Live: «Метрика не подключена»                 | задать счётчик и токен в «Метрика и данные»                      |
| Аналитика пустая, Live работает               | не было синка за период — «Обновить данные из Метрики»           |
| Синк падает с 401/403                         | токен истёк или не видит счётчик — выпустить новый               |
| После смены `APP_SECRET` пропали токены/ключи | секреты не расшифровываются — ввести заново                      |
| GigaChat: «fetch failed»                      | нет Russian Trusted Root CA / `NODE_EXTRA_CA_CERTS` на сервере   |
| DataLens не присылает код                     | URL устарел после «Выпустить новый URL» — скопировать актуальный |
| Аналитик видит «Нет доступа»                  | админский раздел; при необходимости сменить роль                 |
