# Хэллоуинская воронка

> Как читать воронку хэллоуинского тарифа ProductCamp: цели счётчика, особенности чтения данных
> и известные искажения. Общая механика воронки — [Метрика и цели](Metrika-and-Goals.md),
> Live-эндпоинт — `/api/live/funnel` (см. [Home](Home.md)).

## Цели счётчика (хэллоуин)

| ID цели   | Событие                     | Роль в воронке                              |
| --------- | --------------------------- | ------------------------------------------- |
| 676226258 | `ticket_halloween`          | **Главная цель — покупка** (buy-шаг тарифа) |
| 676226275 | `ticket_pick_halloween`     | Выбор билета (pick)                         |
| 676226284 | `ticket_checkout_halloween` | Переход к оплате (checkout)                 |

> В счётчике цель покупки названа `ticket_halloween` — **без сегмента `buy`**, тогда как
> pc-goals-референс ожидает `ticket_buy_halloween`. Читающая сторона (live-воронка) алиасит
> это имя (ANA-111), поэтому в отчётах шаг buy для хэллоуина корректен.

## Воронка

Основная цепочка тарифа:

```
визиты → price_view → pick → buy → checkout
```

- **visits** — `ym:s:visits` за период (не цель).
- **price_view** — увидел блок билетов.
- **pick** → **buy** → **checkout** — цели хэллоуина из таблицы выше.
- **Оплата считается отдельно** — в основную воронку не входит: цель оплаты
  (`payment_success`/аналог) либо ручные платежи, как и на общей воронке («заявка ≠ оплата»).

## Особенности чтения данных

- **pick занижен по природе.** Не все посетители, дошедшие до выбора, проходят через цель
  `ticket_pick_halloween` — конверсию от price_view к pick интерпретировать как нижнюю границу.
- **До 20:00 МСК 29.10 данные только в `cta_click` / `cart_open`** с `ticket_type=halloween`:
  до этого момента цели хэллоуина в счётчике не существовало, и ранние периоды по целям
  676226258/676226275/676226284 пустые или неполные — не считать это падением воронки.
- **`env=test` исключать.** Тестовые визиты с `env=test` попадают в счётчик; при чтении воронки
  фильтруйте их, иначе числа будут завышены.
- Live-воронка (`/app/live`) читает Reporting API напрямую (в БД не пишет), значения —
  достижения целей `ym:s:goal<ID>reaches` за выбранный период.
