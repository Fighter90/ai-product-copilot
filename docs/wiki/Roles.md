## Две роли

|                                                   | **Администратор** | **Аналитик**                                    |
| ------------------------------------------------- | ----------------- | ----------------------------------------------- |
| Аналитика (Обзор, Live, KPI, воронка, «Исследуй») | ✅                | ✅                                              |
| Отчёты, история, B2B                              | ✅                | ✅                                              |
| DataLens (страница, CSV-экспорт)                  | ✅                | ✅                                              |
| Пользователи и роли                               | ✅                | ❌ (прямой переход на `/app/admin/*` → 403)     |
| AI-провайдеры и ключи                             | ✅                | ❌                                              |
| Метрика (синк, цели)                              | ✅                | ❌ (если не выдан доступ к счётчику — см. ниже) |
| Аудит, интеграции                                 | ✅                | ❌                                              |

## Как это работает

- Права проверяются **на бэкенде** (guard `onRequest`: `/api/admin/**` — только admin) и в UI
  (`RequireAdmin`): без сессии `/app/*` → редирект `/login?next=…`, analyst на admin-странице →
  панель «Нет доступа».
- Пароли — scrypt, сессии — HttpOnly-cookie `pca_session`, в БД только sha256-хэш токена.
- Ограничение входа: 5 неудач за 15 минут на пару ip+email → 429.
- Первый администратор создаётся при старте из `ADMIN_EMAIL`/`ADMIN_PASSWORD`, когда таблица
  `users` пуста.

## Доступ аналитика к счётчику (ANA-29)

По умолчанию аналитик не видит данные Метрики. Админ выдаёт доступ на странице
**Администрирование → Пользователи** (привязка счётчиков, `user_counters`); администраторы
имеют доступ всегда.
