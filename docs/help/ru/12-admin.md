# Администрирование

Раздел «Админ» доступен только роли «Администратор»: Пользователи, AI-провайдеры, Метрика и данные, Интеграции, Аудит.

## Пользователи

![Скриншот: пользователи](/screenshots/17-admin-users.png)
_«Админ → Пользователи»: список аккаунтов, роли и активность._

Workflow «создать пользователя»:

1. «Админ → Пользователи» → «Добавить».
2. Введите e-mail, имя, выберите роль (администратор или аналитик).
3. Задайте пароль и передайте его пользователю по защищённому каналу.
4. Убедитесь, что пользователь вошёл, — первая запись о нём появится в аудите.

Операции с аккаунтами:

| Операция             | Эффект                                                  |
| -------------------- | ------------------------------------------------------- |
| Деактивация          | Вход запрещён, история действий и аудит сохраняются     |
| Смена пароля         | Старый пароль мгновенно перестаёт работать              |
| Смена роли           | Права применяются сразу; недоступное API возвращает 403 |
| Редактирование имени | Отображается в журнале аудита                           |

## AI-провайдеры

![Скриншот: ai-провайдеры](/screenshots/18-admin-ai.png)
_«Админ → AI-провайдеры»: выбор провайдера, ключ, модель, параметры, кнопка «Проверить»._

Поддерживаются четыре провайдера. Общие поля: API-ключ и модель; у части провайдеров есть дополнительные параметры.

| Провайдер  | Обязательные поля          | Примеры моделей                                      | Особенности                               |
| ---------- | -------------------------- | ---------------------------------------------------- | ----------------------------------------- |
| OpenRouter | API-ключ, модель           | Модели разных вендоров через один ключ               | Удобен как «универсальный» вход           |
| Anthropic  | API-ключ, модель           | claude-sonnet-5-5, claude-haiku-5-5, claude-opus-5-5 | Новые модели не принимают temperature     |
| YandexGPT  | API-ключ, модель, folderId | yandexgpt/latest, yandexgpt-lite/latest              | Без folderId запрос не собирается         |
| GigaChat   | API-ключ, модель, scope    | GigaChat-2, GigaChat-2-Pro, GigaChat-2-Max           | Scope: GIGACHAT_API_PERS / \_B2B / \_CORP |

Workflow «подключить провайдера»:

1. «Админ → AI-провайдеры» → выберите провайдера.
2. Вставьте API-ключ, выберите модель; для YandexGPT укажите folderId, для GigaChat — scope.
3. Нажмите «Проверить» — выполняется тестовый запрос к провайдеру.
4. Убедитесь, что тест вернул текст, и сохраните.
5. Проверьте расход в журнале использования (`GET /api/admin/ai/usage`).

Что значат ошибки проверки:

| Сообщение               | Причина                                          |
| ----------------------- | ------------------------------------------------ |
| 401 / «unauthorized»    | Неверный или отозванный ключ                     |
| 404 / «model not found» | Модель недоступна вашему ключу — выберите другую |
| «folderId is not set»   | YandexGPT: не заполнен ID каталога               |
| 403 / «scope»           | GigaChat: scope не соответствует типу ключа      |
| Таймаут                 | Провайдер недоступен — повторите позже           |

Ключи шифруются AES-256-GCM мастер-ключом `APP_SECRET` и в ответах API маскируются — полный ключ не видно никому, включая администратора.

## Метрика и данные

![Скриншот: метрика](/screenshots/19-admin-metrika.png)
_«Админ → Метрика»: состояние счётчика, ручной синк, создание/архивация целей, очистка данных._

Основные операции:

- **Проверка счётчика** — кабинет работает со счётчиком 54280963; страница показывает доступность и свежесть данных.
- **Ручной синк** — подтягивает за период цели, каналы, UTM, гео, страницы и страницы выхода. Плановый синк выполняется по расписанию systemd каждые 3 часа; ручной нужен после создания целей или при пустых днях.
- **Создание цели** — через Management API Метрики: тип (URL, JS-событие и др.), название, условия. Новая цель появится в «Целях» после следующего синка.
- **Архивация цели** — помечает цель архивной (учитывается `ARCHIVED_GOAL_ID_THRESHOLD`), из KPI она исчезает.
- **Очистка данных** — удаляет дневные данные из базы; запускать осознанно, после неё выполнить полный синк.

Workflow «завести цель под кампанию»:

1. Определите событие или URL, который считаем целью (согласуйте с разработчиком сайта).
2. «Админ → Метрика → Создать цель»: выберите тип и условия.
3. Запустите ручной синк, чтобы цель попала в кабинет.
4. Проверьте появления цели на «Live» в день запуска кампании.
5. Если цель должна стать основной — задайте `GOAL_ID` или проверьте авто-детект.

**Настройки (файл .env на сервере, см. docs/deploy.md):**

- `COUNTER_ID` — идентификатор счётчика (у ProductCamp: 54280963).
- `YANDEX_OAUTH_TOKEN` — OAuth-токен с правом чтения Метрики; получить: приложение на oauth.yandex.ru (scope `metrika:read`) → открыть ссылку авторизации → скопировать `access_token` из адресной строки.
- `GOAL_ID` — зафиксировать KPI-цель вручную (по умолчанию — авто-детект цели покупок).
- `ARCHIVED_GOAL_ID_THRESHOLD` — порог архивности целей по id (fallback; приоритет у полей `archived`/`status` API).
- `INCLUDE_TEST_TRAFFIC=1` — отключить фильтр служебного трафика (по умолчанию роботы и локальные визиты исключены и из синка, и из live).

**Типы условий целей:** Management API принимает exact / contain / start / regexp по URL. Тип `js` API отвергает — JS-события оформляются как цель типа action с URL-условием (сайтом отправляется запрос, совпадающий с условием).

## Интеграции

![Скриншот: интеграции](/screenshots/20-admin-integrations.png)
_«Админ → Интеграции»: токен вебхуков DataLens и состояние интеграций._

Токен вебхуков DataLens:

1. Скопируйте токен на странице «Интеграции».
2. Вставьте его в URL вебхука в настройках алерта DataLens: `…/webhook/{token}`.
3. При компрометации токена перегенерируйте его и обновите URL в DataLens.

## Аудит

Журнал фиксирует: входы, изменение настроек, создание и архивацию целей, выгрузки, запросы DataLens. Записи неизменяемы. Используйте аудит, чтобы ответить «кто и когда изменил настройку» и разобрать инциденты.

## Кейсы

- **«Настроить AI-анализ отчётов»** — выберите провайдера (например, Anthropic), вставьте ключ, «Проверить», затем на странице «Отчёт» проверьте AI-анализ снапшота.
- **«Дни в истории пустые»** — «Админ → Метрика» → ручной синк за нужный период → проверьте «Историю».
- **«Уволился аналитик»** — «Пользователи» → деактивация: доступ закрыт, аудит сохранён.
- **«Настроить алерты DataLens»** — скопируйте токен в «Интеграции», вставьте в URL алерта, проверьте уведомление в кабинете.

## Частые проблемы

| Проблема                           | Причина и решение                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------------------- |
| «Проверить» у провайдера падает    | См. таблицу ошибок: чаще неверный ключ или незаполненный folderId/scope.                    |
| Синк завершается с ошибкой         | Квоты или токен Метрики — повторите позже; плановый синк каждые 3 часа дозаполнит пропуски. |
| Пользователь «не может войти»      | Аккаунт деактивирован или пароль не подходит — проверьте статус в «Пользователях».          |
| Сброс пароля по e-mail не работает | Такого механизма нет — пароль задаёт администратор вручную.                                 |
| Вебхуки DataLens не доходят        | Токен не тот или был перегенерирован — сверьте URL в настройках алерта.                     |
