# Как устроен продукт

## Слои

| Слой         | Технология        | Ответственность                                            |
| ------------ | ----------------- | ---------------------------------------------------------- |
| Клиент       | React SPA         | Страницы кабинета, графики ECharts, таблицы, i18n, темы    |
| API          | Fastify (Node.js) | Авторизация, роли, расчёты, отчёты DOCX/PDF, вебхуки       |
| База         | SQLite            | Дневные данные Метрики, пользователи, снапшоты, B2B, аудит |
| Источник     | Яндекс.Метрика    | Reporting API (данные) и Management API (цели)             |
| Визуализация | Yandex DataLens   | Дашборды вне кабинета, алерты через вебхуки                |

## Путь данных

1. Сайт productcamp.ru шлёт события в Метрику (счётчик 54280963), включая JS-события pc-goals.
2. Синк-служба на сервере каждые 3 часа (systemd-таймер) запрашивает Reporting API и складывает данные по дням в SQLite: визиты, каналы, UTM, гео/устройства, страницы, достижения целей.
3. API читает SQLite и отдаёт агрегаты клиенту — страницы быстрые и не зависят от доступности Метрики.
4. Страницы Live работают иначе: прямой запрос в Reporting API за сегодня — данные свежие, но действуют квоты Метрики.
5. DataLens получает копии данных CSV-файлами, а его алерты возвращаются в кабинет вебхуками.

## Что происходит при открытии страницы

1. Клиент проверяет сессию (cookie) и запрашивает данные у API.
2. API проверяет роль: административные эндпоинты для аналитика возвращают 403.
3. Данные берутся из SQLite (дневные) или напрямую из Метрики (Live).
4. Клиент рисует таблицы и графики; выбранный период передаётся на каждую страницу.

## Реальное время vs дневные данные

| Аспект    | Дневные данные (синк)          | Live                       |
| --------- | ------------------------------ | -------------------------- |
| Свежесть  | До 3 часов (расписание)        | Момент запроса             |
| Объём     | Вся история по дням            | Сегодня и короткие периоды |
| Стоимость | Один запрос на много дней      | Запрос на каждый просмотр  |
| Где       | Обзор, Трафик, Воронка, Отчёты | Live, воронка pc-goals     |

## Где живут данные

- **SQLite (файл на сервере)** — всё состояние: дневные ряды, пользователи (пароли — хэши), снапшоты отчётов, гипотезы, B2B-сделки, журнал аудита, настройки.
- **Метрика** — первичный источник; кабинет не хранит сырые визиты, только дневные агрегаты.
- **DataLens** — собственные копии CSV, загруженные аналитиком; живут отдельно от кабинета.

## Роли и права (RBAC)

| Действие                                     | Администратор | Аналитик  |
| -------------------------------------------- | ------------- | --------- |
| Просмотр дашбордов, Live, целей, отчётов     | Да            | Да        |
| Снапшоты, DOCX/PDF, гипотезы, AI-анализ      | Да            | Да        |
| B2B-сделки, DataLens-экспорт                 | Да            | Да        |
| Пользователи (создание, деактивация, пароли) | Да            | Нет (403) |
| AI-провайдеры (ключи, проверка)              | Да            | Нет (403) |
| Синк Метрики, создание/архивация целей       | Да            | Нет (403) |
| Токены интеграций, аудит                     | Да            | Нет (403) |

## Безопасность и секреты

- Пароли пользователей хранятся хэшами; сессии — подписанные cookie на 7 дней (с «Запомнить меня»).
- API-ключи AI-провайдеров шифруются AES-256-GCM мастер-ключом `APP_SECRET` и в ответах API маскируются.
- Токен вебхуков DataLens — отдельный секрет для URL алертов; перегенерируется в «Админ → Интеграции».
- CSV-выгрузки защищены от формульных инъекций: значения вида `=…` экранируются, чтобы не исполнялись в Excel.
- Журнал аудита неизменяем: кто, когда и что сделал.

## Кейсы

- **«Почему в Обзоре нет сегодняшнего дня?»** — дневные данные приходят синком каждые 3 часа; за сегодня смотрите «Live».
- **«Кто изменил настройку интеграции?»** — «Админ → Аудит»: записи неизменяемы и содержат пользователя и время.
- **«База потерялась — что восстанавливать?»** — последний бэкап (04:30) плюс синк вернут дневные данные из Метрики; ручные записи (B2B, гипотезы) восстановятся на момент копии.

## Частые проблемы

| Проблема                           | Объяснение                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| Live и Обзор расходятся за сегодня | Разные источники: прямой запрос против последнего синка (до 3 часов).          |
| После сбоя «день пустой»           | Синк пропустил день — ручной синк дозаполнит его из Метрики.                   |
| Ключ провайдера не видно целиком   | Так задумано: маскирование в API плюс шифрование AES-256-GCM в базе.           |
| Отчёт PDF не собирается            | На сервере нужен Chromium (`PUPPETEER_EXECUTABLE_PATH`); DOCX работает всегда. |
