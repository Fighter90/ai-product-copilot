# Реальное время

## Страницы Live

Раздел «Live» запрашивает данные напрямую из Reporting API Метрики — без ожидания планового синка, который проходит каждые 3 часа:

- **Live-цели** — достижения всех целей за сегодня, сравнение со вчера и с 14/90-дневным средним.
- **Воронка live** — этапы pc-goals: от показа блока билетов до заказа.
- **Детальная страница цели** — разбивка достижения цели: источники, устройства, страницы входа.

## Воронка pc-goals по шагам

Воронка строится по JS-событиям pc-goals на сайте productcamp.ru. Для каждого события в Метрике заведена цель типа «JavaScript-событие»:

| №   | Этап                     | Событие    | Что делает посетитель            |
| --- | ------------------------ | ---------- | -------------------------------- |
| 1   | Увидел блок билетов      | price_view | Доскроллил до блока с тарифами   |
| 2   | Клик по CTA              | cta_click  | Нажал кнопку выбора билета       |
| 3   | Открыл регистрацию       | reg_open   | Начал оформление                 |
| 4   | Открыл корзину           | cart_open  | Дошёл до корзины                 |
| 5   | Оставил контакты (заказ) | reg_step1  | Заполнил контакты — появился лид |

Для каждого этапа считаются две конверсии: к предыдущему шагу и к визитам (первому этапу). Этапы считаются по всем визитам дня, а не как строгая последовательность внутри одной сессии — это обзорная воронка для оценки «где теряем», а не поэтапный учёт сессий.

## Тарифы билетов

По каждому тарифу отслеживаются три события — выбор билета, переход к корзине и покупка:

| Тариф    | Выбор билета         | Переход к оплате         | Покупка             |
| -------- | -------------------- | ------------------------ | ------------------- |
| standard | ticket_pick_standard | ticket_checkout_standard | ticket_buy_standard |
| optimal  | ticket_pick_optimal  | ticket_checkout_optimal  | ticket_buy_optimal  |
| max      | ticket_pick_max      | ticket_checkout_max      | ticket_buy_max      |

Сравнение цепочки «выбор → корзина → покупка» по тарифам показывает, где теряются покупатели: высокий pick при низком checkout — сигнал про цену или описание тарифа.

## Роли заявок

Отдельные события считают заявки вне билетной воронки: заявка волонтёра (volunteer_apply), заявка спикера (speaker_apply), заявка C-level (clevel_apply), заявка партнёра (partner_apply). Они не входят в KPI билетов, но показываются рядом с воронкой — удобно следить за программой конференции и партнёрским потоком.

## Как читать дельту

Дельта — изменение к предыдущему дню на то же время. Отрицательная дельта в первой половине дня — нормальна: сравнивайте с показателем за полный вчерашний день. Дельта к среднему (14/90 дней) надёжнее для оценки тренда, чем сравнение с одним днём, который мог быть аномальным.

## Обновление

Данные запрашиваются при открытии страницы. Кнопка «Обновить» перезапрашивает Метрику; ограничений по частоте нет, но без необходимости не чаще раза в минуту — у Reporting API Метрики есть квоты на запросы.

## Кейсы

- **«Билеты продаются медленнее, чем в прошлую неделю»** — откройте «Воронка live», сравните этапы «Открыл корзину» и «Оставил контакты» со средним; падение на последнем шаге — проверьте форму регистрации.
- **«Какой тариф покупают чаще»** — таблица тарифов, колонка покупок по standard/optimal/max; затем «Исследуй → Источники», чтобы понять, откуда идут покупатели этого тарифа.
- **«Сколько заявок спикеров сегодня»** — блок ролей заявок: событие speaker_apply за текущий день.

## Частые проблемы

| Проблема                             | Причина и решение                                                                                        |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| Этапы воронки равны нулю             | События pc-goals не доходят до Метрики — проверьте цели типа JS-событие и код на сайте.                  |
| Live-данные не совпадают с «Обзором» | Обзор — по дневному синку (задержка до 3 часов), Live — прямой запрос; расхождение за сегодня допустимо. |
| Дельта «−50 %» утром                 | Сравнение неполного дня с полным; смотрите полный вчера или среднее за 14/90 дней.                       |
