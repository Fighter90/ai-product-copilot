# Цели и KPI

## Страница «Цели»

Показывает все цели счётчика с типом, статусом и достижениями. Мёртвые цели (0 достижений за 90 дней) и дубли помечаются автоматически — список удобно чистить перед сезоном продаж.

| Статус   | Условие                                  | Что делать                                  |
| -------- | ---------------------------------------- | ------------------------------------------- |
| Активная | Есть достижения за 14 дней               | Использовать в отчётах и KPI                |
| Спящая   | Достижения были за 90 дней, но нет за 14 | Проверить, жив ли источник события на сайте |
| Мёртвая  | 0 достижений за 90 дней                  | Кандидат на удаление или архивацию          |

_Список целей: типы (URL, JS-событие, количество просмотров…), статусы, достижения за период._

## Выбор основной цели

Основная цель считается в KPI и отчётах. По умолчанию выбирается цель покупок/оплат автоматически (Ecommerce-цель либо наиболее подходящая по смыслу). Администратор может закрепить конкретную цель переменной `GOAL_ID` в настройках сервера — тогда авто-детект отключается, и KPI всегда считается по одной цели.

## Карточка цели

Клик по цели открывает детальную карточку (/app/goals/:id): динамика достижений, конверсия, разбивка по каналам и устройствам, сравнение периодов.

Workflow «разобрать просадку цели»:

1. Откройте «Цели» и найдите цель с падением.
2. В карточке сравните два периода переключателем периода.
3. Посмотрите разбивку по каналам — какой канал просел.
4. Уточните в «Исследуй → UTM», какая кампания дала провал.
5. Зафиксируйте вывод гипотезой в «Отчёт», чтобы вернуться к нему после правок.

## Архивные цели

Цели с идентификаторами выше порога архивации считаются архивными и не участвуют в KPI. Порог настраивается переменной `ARCHIVED_GOAL_ID_THRESHOLD`. Переключатель «Архивные цели» на странице показывает или скрывает их — при разборе истории кампаний включайте показ архивных.

## Создание целей из кабинета

Администратор может создать или заархивировать цель прямо из кабинета через «Админ → Яндекс.Метрика» (используется Management API Метрики) — например, завести цель под новую кампанию без входа в интерфейс Метрики. Пошаговая инструкция — в статье «Администрирование».

## Кейсы

- **«Настроить новую цель»** — администратор: «Админ → Яндекс.Метрика → Создать цель» → тип JS-событие → имя события с сайта → ручной синк → проверить появления цели на «Live».
- **«Почему KPI считает не ту цель»** — посмотрите авто-детект на странице «Цели»; если он ошибается, администратор фиксирует `GOAL_ID`.
- **«Чистка целей перед сезоном»** — отсортируйте по статусу, мёртвые цели отправьте в архив, спящие проверьте на сайте.

## Частые проблемы

| Проблема                            | Причина и решение                                                                |
| ----------------------------------- | -------------------------------------------------------------------------------- |
| Цель есть в Метрике, в кабинете нет | Синк ещё не забирал изменения — запустите синк вручную.                          |
| Достижений 0, хотя сайт работает    | Цель типа URL, а страница сменила адрес; либо опечатка в имени JS-события.       |
| KPI «прыгает» между целями          | Работает авто-детект — попросите администратора закрепить `GOAL_ID`.             |
| Архивная цель считается в KPI       | Проверьте `ARCHIVED_GOAL_ID_THRESHOLD` — порог мог не охватить её идентификатор. |

## Источник данных и границы

Список целей приходит из каталога Метрики при синке (таблица `goals`: id, имя, тип, флаг
архива). Достижения в карточке — дневные ряды из `channel_stats`/`raw_responses`, поэтому
карточка отражает тот же период, что и фильтр в шапке. Управление (создание/архив) доступно
админу через Management API Метрики; аналитику — только просмотр. Если цель создана в
интерфейсе Метрики — дождитесь синка, чтобы она появилась в кабинете.

## Типы целей и их особенности

| Тип | Как срабатывает | На что смотреть |
| --- | --------------- | --------------- |
| URL-условие | Посещение страницы по маске (contain/start/regexp) | Маска не должна переживать редизайн |
| JS-событие | `ym(…, 'reachGoal', name)` с сайта | Точное имя события, без опечаток |
| Количество просмотров | N страниц за визит | Глубина, а не конверсия |
| Ecommerce/заказ | Данные электронной коммерции | Основной кандидат в `GOAL_ID` |

## Связанные страницы

- **Live → Цели** — достижения целей за сегодня (Reporting API, без ожидания синка).
- **Маркетинг** — строка «цели на сайте» в недельной сетке считает ту же основную цель по неделям.
