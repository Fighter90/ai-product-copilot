# Руководство администратора

Администратор видит всё, что видит аналитик (см. «Руководство аналитика», `/help/analyst-guide`), плюс раздел «Администрирование» в сайдбаре. Все админские запросы проверяются на сервере: адреса `/api/admin/*`, `/api/users`, изменение настроек и удаление данных доступны только роли «Администратор», остальным — HTTP 403.

Первый администратор создаётся при первом запуске из `ADMIN_EMAIL` / `ADMIN_PASSWORD` в `.env`, если таблица пользователей пуста. Дальше пользователей заводят в интерфейсе.

## Порядок первичной настройки

1. «Метрика и данные» — счётчик и OAuth-токен, «Сохранить».
2. Там же — «Обновить данные из Метрики» за нужный период.
3. «AI-провайдеры» — хотя бы один провайдер с ключом (`/help/llm-keys`).
4. «Пользователи» — завести аналитиков и выдать им временные пароли.
5. «Интеграции» — при необходимости DataLens: подключение API, URL вебхука, ссылки на дашборды.
6. «Журнал действий» — проверить, что все шаги записались.

## Пользователи (`/app/admin/users`)

**Назначение.** Учётные записи, роли и доступ.

![Скриншот: пользователи](/screenshots/17-admin-users.png)
_Таблица пользователей и кнопка «Добавить пользователя»._

| Элемент                    | Что делает                                                                                              |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| «Добавить пользователя»    | окно с полями «Имя», «Email», «Роль» (по умолчанию «Аналитик»), кнопка «Сохранить»                      |
| Карточка временного пароля | после создания или сброса — «Временный пароль (показывается один раз)», кнопки «Копировать» и «Закрыть» |
| Колонки таблицы            | Имя (метка `you` у вашей записи), Email, Роль, Статус (активен / отключён), Последний вход              |
| Список «Роль» в строке     | меняет роль сразу при выборе: Администратор / Аналитик                                                  |
| «Сбросить пароль»          | выпускает новый временный пароль и завершает все сессии пользователя                                    |
| «Отключить» / «Включить»   | блокирует вход; при отключении все активные сессии пользователя завершаются немедленно                  |

**Сценарии.**

- _Новый аналитик:_ «Добавить пользователя» → имя, email, роль «Аналитик» → «Сохранить» → «Копировать» пароль → передайте его человеку защищённым каналом. Повторно пароль не показывается.
- _Забыли пароль:_ найдите пользователя → «Сбросить пароль» → передайте новый временный пароль. Отдельной формы смены пароля в интерфейсе нет — сброс делает администратор.
- _Сотрудник ушёл:_ «Отключить». Запись и её история в журнале сохраняются, вход и сессии блокируются.
- _Второй администратор:_ смените роль в строке на «Администратор». Держите минимум двух активных администраторов.

**Ошибки.** «Email уже существует» — пользователь с таким email уже есть (включите его или сбросьте пароль). «Нельзя отключить или понизить последнего администратора» — сначала назначьте другого администратора.

## AI-провайдеры (`/app/admin/ai`)

**Назначение.** Ключи и порядок четырёх провайдеров (OpenRouter, Anthropic, YandexGPT, GigaChat) для AI-анализа отчёта, AI-гипотез и ассистента.

Кратко: в каждой карточке — «Ключ», «Модель», «Приоритет» (меньше — раньше в цепочке), доп. поля (folder ID у YandexGPT, scope у GigaChat), «Сохранить», «Проверить соединение», галочка «Включён». Ниже — «Использование за 30 дней» (вызовы и ошибки по провайдерам). Ключи шифруются AES-256-GCM и показываются только маской.

Подробная инструкция по каждому провайдеру, сценарии и разбор ошибок — статья «Ключи LLM-провайдеров» (`/help/llm-keys`).

## Метрика и данные (`/app/admin/metrika`)

**Назначение.** Подключение счётчика, цели KPI, синхронизация в SQLite и очистка кэша.

![Скриншот: Метрика и данные](/screenshots/19-admin-metrika.png)
_Карточки «Подключение», «Синхронизация в SQLite» и «Опасная зона»._

### Карточка «Подключение»

Возле каждого поля — метка источника значения: `db` (задано в админке), `env` (взято из `.env`), `unset` (не задано).

| Поле                 | Ключ                   | Что вводить                                                                                     |
| -------------------- | ---------------------- | ----------------------------------------------------------------------------------------------- |
| Счётчик Метрики      | `COUNTER_ID`           | номер счётчика, например `54280963`                                                             |
| OAuth-токен          | `YANDEX_OAUTH_TOKEN`   | токен с правом `metrika:read` (и `metrika:write` для управления целями); хранится зашифрованным |
| Client ID приложения | `YANDEX_CLIENT_ID`     | ID OAuth-приложения — нужен для получения токена командой `pnpm auth`                           |
| Client secret        | `YANDEX_CLIENT_SECRET` | секрет OAuth-приложения; хранится зашифрованным                                                 |
| Цель «Заказ»         | `ORDER_GOAL_ID`        | ID цели заказа для live-страниц; по умолчанию — JS-событие `reg_step1`                          |
| Цель KPI для отчёта  | `GOAL_ID`              | `0` — автоопределение цели-покупки при синке                                                    |
| Цель по оплатам      | `KPI_TARGET`           | целевое число оплат, например 300                                                               |

Кнопка «Сохранить» применяет изменения **сразу, без перезапуска сервера** (клиент Метрики пересобирается). После сохранения вверху появится строка «Сохранить: …» со списком изменённых ключей; клик по ней скрывает сообщение.

Секретные поля показывают маску `••••abcd`. Если маску не трогать, значение сохранится прежним; чтобы заменить секрет, сотрите маску и вставьте новое значение.

Уточнения по текущей версии: ручной синк всегда автоматически определяет основную цель-покупку, а `GOAL_ID` используется как запасная «цель заказа» для live-страниц, если «Цель «Заказ»» не задана. Значение «Цель по оплатам» сохраняется в настройках, но KPI-полосы и отчёт считают цель 300, заданную в продукте.

**Как получить OAuth-токен.**

1. На oauth.yandex.ru создайте приложение (ссылка есть в подсказке над формой) с доступами `metrika:read` и `metrika:write`.
2. Выпустите токен для аккаунта, у которого есть доступ к счётчику (или выполните `pnpm auth` с Client ID / Client secret — команда запишет токен в `.env`).
3. Вставьте токен в поле «OAuth-токен» → «Сохранить».
4. Проверьте страницу «Сейчас»: если данные появились, токен и счётчик верны.

### Карточка «Синхронизация в SQLite»

Кнопка «Обновить данные из Метрики» загружает агрегаты Метрики за период глобального фильтра (по умолчанию — последние 14 дней; период меняется фильтром на страницах аналитики): каналы, UTM, гео и устройства, страницы входа и выхода, цели. Эти данные нужны отчёту и страницам «Обзор», «Трафик», «Поведение», «Воронка и B2B», «KPI и прогноз».

После завершения вверху появится строка «Sync: {…}» с итогами: число целей, ID найденной основной цели, число дней и строк по каждому разрезу. Ошибка показывается под кнопкой.

На сервере синк дополнительно выполняется автоматически каждые 30 минут (`pca-sync.timer`). Ручной синк нужен после смены счётчика или токена, после создания целей и для загрузки длинной истории (выберите период до 365 дней).

### Опасная зона

«Очистить данные Метрики» → в окне введите слово `УДАЛИТЬ` → «OK». Удаляются сырые ответы Метрики (`raw_responses`) и производные таблицы (каналы, UTM, гео/устройства, страницы входа и выхода). **Сохраняются** отчёты-срезы, гипотезы, B2B-сделки, пользователи и настройки. После очистки сразу запустите синк, иначе страницы аналитики будут пустыми. Действие пишется в журнал как `data.clear_metrika`.

### Цели Метрики: создание, архивация, восстановление

Управление целями идёт через Management API Метрики и требует токен с правом `metrika:write`. В текущей версии интерфейса отдельной формы для этого нет — операции доступны администратору как API-эндпоинты (работают в рамках вашей сессии в кабинете):

| Операция     | Запрос                                       | Тело                                                                                   |
| ------------ | -------------------------------------------- | -------------------------------------------------------------------------------------- |
| Создать цель | `POST /api/admin/metrika/goals`              | `{"name": "…", "type": "action", "conditions": [{"type": "exact", "url": "событие"}]}` |
| Архивировать | `POST /api/admin/metrika/goals/<ID>/archive` | необязательно `{"folderId": N}` — папка архива                                         |
| Восстановить | `POST /api/admin/metrika/goals/<ID>/restore` | —                                                                                      |

Правила: типы целей — `url`, `action`, `step`, `number`, `visit_duration`, `email`, `file`, `phone`, `search`, `social`, `chat`, `messenger`, `payment_system`. Типы условий — `exact`, `contain`, `start`, `regexp`. Тип условия `js` Метрика не принимает: JS-событие оформляется целью типа `action` с условием по идентификатору события. Целям `url` и `action` нужно хотя бы одно условие, цели `step` — хотя бы один шаг. Новая цель появится в кабинете после следующего синка. Все операции пишутся в журнал (`metrika.goal_created`, `metrika.goal_archived`, `metrika.goal_restored`).

Ошибки управления целями:

| Сообщение                                                                | Что делать                                                          |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| Metrika is not configured (409)                                          | задайте счётчик и токен в «Подключении»                             |
| Метрика отклонила цель — проверьте параметры (400)                       | исправьте тип, условия или название по тексту ошибки                |
| OAuth-токен недействителен или истёк (401)                               | выпустите новый токен                                               |
| Токену недоступен этот счётчик либо нет права edit (metrika:write) (403) | выпустите токен с `metrika:write` от аккаунта с доступом к счётчику |
| Цель не найдена в счётчике (404)                                         | проверьте ID цели — возможно, она уже удалена или архивирована      |
| Превышен лимит запросов к API Метрики (429)                              | повторите позже                                                     |

## Интеграции (`/app/admin/integrations`)

**Назначение.** Связь с Яндекс DataLens: доступ к Public API, вебхук-приёмник и ссылки на дашборды для аналитиков.

![Скриншот: интеграции](/screenshots/20-admin-integrations.png)
_Подключение DataLens, URL вебхука, последний код и события._

### Подключение DataLens

| Поле / кнопка           | Что делает                                                                                                                                                        |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Org ID (ID организации) | datalens.ru → Настройки организации → ID организации                                                                                                              |
| Workbook ID             | ID воркбука из адреса `datalens.ru/workbooks/<ID>`                                                                                                                |
| IAM-токен               | `yc iam create-token` (живёт не более 12 часов) или IAM-токен сервисного аккаунта с ролью в организации DataLens; хранится зашифрованным, пустое поле = не менять |
| «Сохранить»             | сохраняет поля, применяется сразу; сообщение «Сохранено: …»                                                                                                       |
| «Проверить подключение» | запрос к DataLens API; успех — «Подключение к DataLens работает · Воркбук: …»                                                                                     |

Ошибки проверки: «Не заполнено: …» — заполните перечисленные поля; «HTTP 401: IAM-токен недействителен или истёк» — выпустите новый токен; «HTTP 403: нет доступа» — проверьте Org ID и роль в организации; «HTTP 404: воркбук не найден» — проверьте Workbook ID; «Таймаут запроса к DataLens (15 с)» или «Сеть: DataLens API недоступен» — проблемы сети с сервера.

### Вебхук DataLens (токен приёмника)

- В карточке «URL вебхука для DataLens» показан адрес вида `https://<домен>/api/integrations/datalens/webhook/<токен>` и кнопка «Копировать». Токен в адресе — это и есть защита приёмника.
- «Выпустить новый URL» генерирует новый токен; **старый адрес сразу перестаёт работать** — обновите его в DataLens. Действие пишется как `datalens.token_rotated`.
- Подключение: DataLens → Настройки → Уведомления → Вебхуки → «Добавить вебхук» → вставьте URL → «Получить код» → через несколько секунд код появится в карточке «Последний код подтверждения» → введите его в DataLens.
- «События от DataLens» — последние входящие события (код подтверждения и алерты) с временем и содержимым; список обновляется каждые 5 секунд. События также приходят в колокольчик уведомлений.

### Ссылки на дашборды

Поле «Ссылки на дашборды DataLens (по одной в строке)» → «Сохранить». Ссылки, начинающиеся с `http://` или `https://`, появятся у всех пользователей на странице «DataLens» в блоке «Дашборды DataLens команды».

### Запросы аналитиков

Аналитик на странице «DataLens» может отправить «Попросить администратора подключить» с комментарием. Администраторам приходит уведомление в колокольчик, запрос пишется в журнал (`datalens.request`). Лимит — 3 запроса в час на пользователя.

## Журнал действий (`/app/admin/audit`)

**Назначение.** Ответ на вопрос «кто, когда и что изменил». Записи только добавляются; секреты в журнал не попадают.

Таблица показывает последние 1000 записей и обновляется каждые 30 секунд. Колонки: Когда, Кто, Действие, Объект, Детали (первые 120 символов). Доступны поиск, сортировка по колонкам, выбор колонок, постраничный просмотр и «Скачать CSV».

| Группа       | Действия                                                                          |
| ------------ | --------------------------------------------------------------------------------- |
| Вход         | `auth.login`, `auth.login_failed`, `auth.logout`, `auth.password_changed`         |
| Пользователи | `users.create`, `users.update`, `users.reset_password`                            |
| Настройки    | `settings.update` (список изменённых ключей), `data.clear_metrika`                |
| AI           | `ai.provider_update`, `ai.provider_test`                                          |
| Метрика      | `metrika.goal_created`, `metrika.goal_archived`, `metrika.goal_restored`          |
| DataLens     | `datalens.export`, `datalens.request`, `datalens.check`, `datalens.token_rotated` |

**Сценарии.** «Почему пропали данные?» — ищите `data.clear_metrika`. «Кто поменял токен?» — `settings.update` с `YANDEX_OAUTH_TOKEN` в объекте. «Подбор пароля?» — серия `auth.login_failed` по одному email (после 5 неудач за 15 минут вход блокируется).

## Ежедневная и еженедельная рутина администратора

- **Ежедневно:** колокольчик (запросы аналитиков, события DataLens); «Сейчас» — данные идут; при пустых днях — ручной синк.
- **Еженедельно:** «Использование за 30 дней» у AI-провайдеров (рост ошибок — повод проверить ключи и баланс); журнал на `auth.login_failed`; актуальность списка пользователей.
- **По событию:** истёк токен Метрики — новый токен и синк; ушёл сотрудник — «Отключить»; новая кампания — цель через API и синк.

## Частые проблемы

| Симптом                                          | Причина и решение                                                |
| ------------------------------------------------ | ---------------------------------------------------------------- |
| Live-страницы показывают «Метрика не подключена» | не заданы счётчик или токен — «Метрика и данные» → «Подключение» |
| Аналитика пустая, Live работает                  | не было синка за период — «Обновить данные из Метрики»           |
| Синк падает с 401/403                            | токен истёк или не видит счётчик — выпустите новый               |
| После смены `APP_SECRET` пропали токены и ключи  | секреты не расшифровываются — введите их заново                  |
| Аналитик видит «Нет доступа»                     | это админский раздел; при необходимости смените ему роль         |
| DataLens не присылает код                        | URL устарел после «Выпустить новый URL» — скопируйте актуальный  |
