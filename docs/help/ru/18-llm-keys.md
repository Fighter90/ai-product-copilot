# Ключи LLM-провайдеров

AI в продукте нужен для трёх вещей: AI-анализа отчёта, AI-гипотез с Decision Log и ассистента по справке. Всё остальное (дашборды, цели, воронка, DOCX/PDF) работает и без AI. Ключи вводит только **администратор** на странице «Администрирование → AI-провайдеры» (`/app/admin/ai`).

## Карточка провайдера: поля и кнопки

| Элемент                | Что делает                                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Метки `on` / `off`     | включён ли провайдер в цепочку                                                                                                           |
| Метка `••••abcd`       | маска сохранённого ключа (последние 4 символа); полностью ключ не показывается никогда                                                   |
| Галочка «Включён»      | включает/выключает провайдера; сохраняется сразу, без кнопки «Сохранить»                                                                 |
| «Ключ · …»             | секрет провайдера (подпись поля зависит от провайдера). Пустое поле при сохранении = «оставить текущий ключ»                             |
| «Модель»               | поле с подсказками из списка; можно вписать и любую другую модель, которую поддерживает провайдер                                        |
| «Приоритет»            | число 0–1000. **Меньше — раньше** в цепочке. По умолчанию: OpenRouter 10, Anthropic 20, YandexGPT 30, GigaChat 40                        |
| Доп. поля              | YandexGPT — «ID каталога (folder ID)»; GigaChat — «Scope (GIGACHAT_API_PERS / _B2B / _CORP)»                                             |
| «Сохранить»            | сохраняет ключ, модель, приоритет и доп. поля                                                                                            |
| «Проверить соединение» | тестовый запрос «Скажи: ок» (таймаут 30 с). Активна, только когда ключ уже сохранён. Результат: «OK · модель · «ответ»» или текст ошибки |
| ссылка «docs»          | документация провайдера                                                                                                                  |

Порядок всегда один: **вставить ключ → заполнить доп. поля → «Сохранить» → «Проверить соединение» → поставить галочку «Включён»**.

## Как работает цепочка (приоритет и фолбэк)

- В работу берутся только провайдеры, у которых стоит «Включён» **и** сохранён ключ.
- Запрос идёт провайдеру с наименьшим приоритетом. При временной ошибке (HTTP 429, 5xx, сбой сети) сначала делается до 2 повторов у того же провайдера с нарастающей паузой (заголовок Retry-After учитывается, но не дольше 10 с). Если провайдер так и не ответил или вернул постоянную ошибку (неверный ключ, таймаут, пустой ответ) — запрос автоматически уходит следующему.
- Тексты ошибок, которые попадают в интерфейс, журнал и статистику, очищаются от всего, похожего на ключи и токены.
- Если отказали все — пользователь видит «Все провайдеры вернули ошибку: …» с причинами по каждому.
- Если не включён ни один — «Нет настроенных AI-провайдеров — администратор включает их в «Администрирование → AI-провайдеры»». Ассистент справки в этом случае отвечает в режиме поиска (показывает подходящие фрагменты статей).

## YandexGPT (Yandex Cloud / AI Studio)

Что нужно: **API-ключ** сервисного аккаунта и **ID каталога** (folder ID).

1. Откройте консоль Yandex Cloud (console.yandex.cloud) или AI Studio (aistudio.yandex.ru) и выберите каталог, в котором будет работать модель. Скопируйте его ID — строка вида `b1g…`.
2. В каталоге создайте **сервисный аккаунт** и выдайте ему роль `ai.languageModels.user` на этот каталог.
3. Для сервисного аккаунта создайте **API-ключ**. Если консоль предлагает выбрать область действия ключа — выберите доступ к языковым моделям (`yc.ai.languageModels.execute`). Секретная часть ключа показывается один раз — сразу скопируйте её.
4. В карточке «YandexGPT (AI Studio)»: поле «Ключ · API-ключ (секретная часть)» — секрет ключа; «ID каталога (folder ID)» — ID из шага 1; модель — `yandexgpt/latest` (или `yandexgpt-lite/latest`, `yandexgpt/rc`).
5. «Сохранить» → «Проверить соединение» → «Включён».

Технически продукт обращается к `llm.api.cloud.yandex.net` с заголовком `Api-Key` и собирает адрес модели как `gpt://<folder ID>/<модель>`. Если в поле «Модель» вписать полный URI, начинающийся с `gpt://`, он используется как есть.

Типичные ошибки: «yandexgpt: folderId is not set» — не заполнен ID каталога; HTTP 401 — неверный или отозванный ключ; HTTP 403 — у сервисного аккаунта нет роли `ai.languageModels.user` или ключ создан в другом каталоге.

## GigaChat (Сбер)

Что нужно: **Authorization Key** и **scope**.

1. Зайдите в личный кабинет на developers.sber.ru, создайте проект GigaChat API.
2. В настройках проекта получите **Authorization Key** (ключ авторизации — base64-строка). Он показывается один раз — сохраните его.
3. Определите **scope** по типу доступа: `GIGACHAT_API_PERS` — физические лица; `GIGACHAT_API_B2B` — юрлица и ИП по предоплаченным пакетам; `GIGACHAT_API_CORP` — юрлица с оплатой по факту. Пустое поле = `GIGACHAT_API_PERS`.
4. В карточке «GigaChat»: «Ключ · Authorization Key» — ключ из шага 2; «Scope» — значение из шага 3; модель — `GigaChat-2`, `GigaChat-2-Pro` или `GigaChat-2-Max`.
5. «Сохранить» → «Проверить соединение» → «Включён».

Как это работает: продукт обменивает Authorization Key на временный access-токен (`ngw.devices.sberbank.ru:9443`), кэширует его до истечения и отправляет запросы в `gigachat.devices.sberbank.ru`.

**Сертификат Russian Trusted Root CA.** Серверы GigaChat используют сертификаты национального удостоверяющего центра Минцифры. Если корневой сертификат «Russian Trusted Root CA» не установлен на сервере, проверка завершится сетевой ошибкой вида «gigachat: fetch failed» (в подробностях — ошибка цепочки сертификатов). Отдельной настройки в продукте для этого нет: администратор сервера скачивает сертификат с Госуслуг (раздел про сертификаты Минцифры) и подключает его к процессу Node.js, например переменной окружения `NODE_EXTRA_CA_CERTS=/путь/к/russian_trusted_root_ca.pem` для сервиса `pca-api`, после чего перезапускает сервис.

Другие ошибки: HTTP 401 на этапе получения токена — неверный Authorization Key или scope не соответствует вашему типу доступа; HTTP 429 — превышен лимит запросов; ошибка об исчерпании токенов — пополните пакет в кабинете developers.sber.ru.

## Anthropic (Claude)

1. Войдите на console.anthropic.com → Settings → API Keys → **Create Key**. Ключ начинается с `sk-ant-` и показывается один раз.
2. Убедитесь, что на аккаунте есть баланс (Plans & Billing) — без него API отвечает ошибкой.
3. В карточке «Anthropic»: «Ключ · API key» — ключ; модель — из подсказок (например, `claude-sonnet-5-5`) или любая актуальная модель из документации.
4. «Сохранить» → «Проверить соединение» → «Включён».

Сервер должен иметь сетевой доступ к `api.anthropic.com`. HTTP 401 — неверный ключ; 400 с упоминанием баланса — пополните счёт; 404 по модели — проверьте название модели.

## OpenRouter

1. Зарегистрируйтесь на openrouter.ai, пополните баланс (Credits) и откройте openrouter.ai/keys → **Create Key**. Ключ начинается с `sk-or-`.
2. В карточке «OpenRouter»: «Ключ · API key» — ключ; модель — в формате `вендор/модель`, например `anthropic/claude-sonnet-4.5`, `openai/gpt-4.1`, `google/gemini-2.5-pro`, `deepseek/deepseek-chat`. Подойдёт любой идентификатор из каталога openrouter.ai/models.
3. «Сохранить» → «Проверить соединение» → «Включён».

OpenRouter удобен как «один ключ ко многим моделям» и хороший первый или резервный провайдер. HTTP 401 — неверный ключ; 402 — закончились кредиты; 404 — нет такой модели.

## Безопасность ключей

- Ключи шифруются **AES-256-GCM**; ключ шифрования выводится из мастер-секрета сервера `APP_SECRET`. В базе хранится только шифротекст.
- API и интерфейс возвращают только маску `••••` + последние 4 символа. Полный ключ после сохранения увидеть нельзя — только заменить.
- В журнал действий пишутся `ai.provider_update` (что изменено; вместо ключа — пометка «changed») и `ai.provider_test` (успех/неуспех). Сам ключ в журнал не попадает.
- Если на сервере сменили `APP_SECRET`, сохранённые ключи перестанут расшифровываться — провайдер станет «без ключа». Введите ключи заново.
- Ключи можно задать и в `.env` (`OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `YANDEX_AI_API_KEY` + `YANDEX_AI_FOLDER_ID`, `GIGACHAT_AUTH_KEY` + `GIGACHAT_SCOPE`) — они подставятся **один раз** при первом запуске, дальше источником истины остаётся эта страница.

## Статистика использования

Блок «Использование за 30 дней» показывает по каждому провайдеру число вызовов и ошибок (тестовые проверки тоже считаются). В базе (`ai_usage`) фиксируются только служебные данные вызова: провайдер, модель, назначение (отчёт, гипотезы, ассистент, тест), пользователь, длительность, размеры запроса и ответа в символах, число токенов (если провайдер его возвращает), текст ошибки. Содержимое вопросов и ответов не сохраняется.

## Типовые сценарии

- **Первое подключение.** Выберите одного провайдера, пройдите шаги из его раздела, добейтесь «OK» в проверке, включите. Затем на странице «Отчёт» сформируйте срез — фоновые AI-гипотезы покажут, что цепочка работает.
- **Основной + резерв.** Например, YandexGPT с приоритетом 10 и GigaChat с приоритетом 20 (оба — российские облака), OpenRouter 30 как последний резерв. Сбой первого автоматически переключит на второй.
- **Смена ключа.** Вставьте новый ключ, нажмите «Сохранить», затем «Проверить соединение». Старый ключ отзовите у провайдера.
- **Временно отключить провайдера.** Снимите галочку «Включён» — ключ сохранится, провайдер просто выпадет из цепочки.

## Частые проблемы

| Симптом                                   | Что проверить                                                                                        |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Кнопка «Проверить соединение» неактивна   | ключ ещё не сохранён — нажмите «Сохранить»                                                           |
| «Ключ не задан»                           | ключ не сохранён или не расшифровывается после смены `APP_SECRET`                                    |
| «timeout after 30000 ms»                  | провайдер недоступен с сервера (сеть, блокировка) — проверьте доступ к его API                       |
| «… fetch failed» у GigaChat               | не установлен Russian Trusted Root CA (см. раздел GigaChat)                                          |
| Проверка «OK», но AI в отчёте не работает | не стоит галочка «Включён»                                                                           |
| «Все провайдеры вернули ошибку»           | читайте причины по каждому провайдеру в тексте ошибки и в счётчике ошибок «Использования за 30 дней» |
