# Отчёты

## Полный цикл: снапшот → документ → гипотеза → решение

1. Выберите период и нажмите «Отчёт → Сформировать». Снапшот фиксирует KPI, каналы, страницы, воронку, достижения целей на момент создания.
2. Проверьте снапшот в списке: данные «заморожены», последующие синки не меняют уже созданный снимок.
3. Скачайте документ: **DOCX** — редактируемый (ГОСТ-совместимая структура), **PDF** — печатная версия. Для PDF на сервере требуется Chromium (переменная `PUPPETEER_EXECUTABLE_PATH`); без него доступен DOCX.
4. Нажмите «→ гипотеза» — из показателей снапшота создастся черновик гипотезы.
5. Доработайте гипотезу, назначьте статус и ответственного.
6. После проверки верните решение в Decision Log — свяжите его со снапшотом как с доказательством.

## Зачем снапшоты

| Вопрос                         | Ответ                                                      |
| ------------------------------ | ---------------------------------------------------------- |
| Данные поменяются после синка? | Нет: снапшот хранит значения на момент формирования.       |
| Можно сравнить два снапшота?   | Да: соседние снапшоты разных периодов показывают динамику. |
| Кто сформировал?               | Автор фиксируется в журнале аудита.                        |

## Гипотезы и Decision Log

Гипотезы и решения ведутся на странице «Отчёт»: статус (новая / в работе / подтверждена / отклонена), доказательства, связь со снапшотом. Так решения не теряются в переписке, а эффект изменений на сайте можно проследить от гипотезы до следующего снапшота.

## AI-анализ: как готовить данные и читать результат

1. Убедитесь, что администратор настроил AI-провайдера («Админ → AI-провайдеры», кнопка «Проверить» возвращает текст).
2. Сформируйте снапшот за осмысленный период (7 или 30 дней, а не один день) — модель анализирует агрегаты снапшота.
3. Нажмите кнопку AI-анализа — провайдер вернёт повествовательный разбор: динамика, сильные и слабые места, рекомендации.
4. Читайте выводы как рекомендации: каждую цифру проверяйте по таблицам снапшота.
5. Полезные выводы переносите в гипотезы — они станут пунктами Decision Log.

Модель видит только агрегированные показатели снапшота — не сырые визиты и не персональные данные.

## Кейсы

- **«Собрать еженедельный отчёт»** — период 7 дней → «Сформировать» → DOCX → правки в Word → отправить; снапшот остаётся в истории как доказательная база недели.
- **«Обосновать изменение бюджета канала»** — снапшот за 30 дней → AI-анализ → выводы в гипотезу → решение в Decision Log со ссылкой на снапшот.
- **«Сравнить две недели между собой»** — два снапшота по 7 дней, сравнение таблиц; расхождения — материал для гипотез.

## Частые проблемы

| Проблема                         | Причина и решение                                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Кнопка PDF недоступна или падает | На сервере нет Chromium — используйте DOCX или попросите администратора настроить `PUPPETEER_EXECUTABLE_PATH`. |
| AI-анализ вернул ошибку          | Провайдер не настроен или кончилась квота — «Админ → AI-провайдеры», журнал использования.                     |
| Выводы AI противоречат таблицам  | Доверяйте таблицам: анализ — рекомендация, а не истина.                                                        |
| Снапшот «не тот»                 | Снапшот фиксирует данные на момент создания — сформируйте новый за нужный период.                              |
| Гипотеза потерялась              | Гипотезы не удаляются, а получают статус «отклонена» — ищите в Decision Log по автору.                         |
