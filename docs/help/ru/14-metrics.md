# Метрики и формулы

## Визиты

**Определение.** Визит — последовательность действий пользователя на сайте; Метрика закрывает визит после периода неактивности (по умолчанию 30 минут).

**Как считается.** Метрика отдаёт метрику `ym:s:visits`; продукт хранит её по дням на уровне каналов, UTM, гео/устройств и страниц.

**Где смотреть.** «Обзор» (KPI-полоса), «Трафик», «История», датасет channels_daily.

**Интерпретация.** Рост визитов сам по себе не успех: смотрите рядом достижения цели и конверсию. Визит ≠ человек: один посетитель может дать несколько визитов за день.

## Посетители

**Определение.** Уникальные посетители за период (по анонимному идентификатору браузера).

**Формулы.** В рамках одного дня посетителей не больше визитов. За период значение не равно сумме дневных: один человек в разные дни — один посетитель периода.

**Типичная ошибка.** Суммировать посетителей по дням — итог завышается. Для периода берите значение из Метрики, а не сумму.

## Отказы (bounce rate)

**Определение.** Доля визитов, в которых был просмотр только одной страницы без иных действий.

**Как считается.** `bounce_rate` хранится как доля (0–1), в интерфейсах — проценты. В CSV-датасетах среднее считается взвешенно по визитам: Σ(bounce × visits) / Σ(visits).

**Интерпретация.** «Отказный» трафик — часто нерелевантная реклама или медленная мобильная страница. Но высокий bounce на информационной статье (прочитал и ушёл) — не всегда плохо.

## Глубина просмотра

**Определение.** Среднее количество просмотров страниц за визит.

**Интерпретация.** Для лендинга с формой низкая глубина нормальна; для контентных разделов рост глубины — вовлечённость. Смотрите вместе со временем на сайте.

## Время на сайте

**Определение.** Средняя длительность визита в секундах (avg_duration).

**Типичная ошибка.** Сравнивать время между сайтами с разными задачами и забывать, что «0 секунд» — частый артефакт отказных визитов, понижающий среднее.

## Конверсия

**Формула.** Конверсия = достижения цели / визиты × 100 %.

**Где смотреть.** KPI-полоса «Обзора», карточка цели, воронки, channels_daily (conversion_rate).

**Интерпретация.** Сопоставляйте конверсию с объёмом: 5 % от 100 визитов хуже для бизнеса, чем 2 % от 10 000. По умолчанию считайте к визитам, а не к посетителям, если не оговорено иное.

## Достижения цели

**Определение.** Число выполнений цели Метрики (URL, действие, JS-событие, составная цель).

**Как считается.** Синк забирает достижения по каждой цели за день; основная цель (KPI) определяется автоматически (Ecommerce/покупки) или фиксируется `GOAL_ID`.

**Типичная ошибка.** Складывать достижения разных целей: цели считаются по-разному, а одно достижение цели в визите не равно одному визиту.

## Заявка ≠ заказ ≠ оплата

**Определения.** Метрика видит только **заявки** (цели-формы) и **заказы** (цель-покупка срабатывает при создании заказа в корзине — контакты оставлены, переход к оплате). **Оплата** — это подтверждённые деньги, и Метрика их не видит.

**Как считается «Оплачено».** Оплачено = B2C-оплаты (вносятся администратором/аналитиком по дням вручную или импортом CSV на странице «Воронка и B2B») + билеты B2B-сделок в стадии «оплачено». KPI-цель и прогноз на «Обзоре» считают именно оплаты; достижения цели-покупки показываются отдельно как «Заказы».

**Типичная ошибка.** Считать заказы оплатами: по данным Logs API цель-покупка срабатывает вместе с `reg_step1` — это создание заказа, а не деньги.

## Тестовый трафик

**Определение.** Роботы, визиты с параметром `env=test` (скрипт pc-goals), песочница `file://`, а также тестовые страницы и UTM из списка администратора (настройка `TEST_TRAFFIC_PATTERNS`). По умолчанию исключён из синка; роботы отсекаются настройкой счётчика.

**Где смотреть.** Переключатель «Показать тестовый трафик» в фильтрах (только для администраторов). Виртуальные просмотры Тильды (`/tilda/popup/…`, `/tilda/click/…`) — события, а не страницы: они группируются в одну строку `/tilda/*` и не считаются страницами входа.

## Демо-данные

**Определение.** Выдуманный набор от `pnpm seed` (последние 30 дней) для знакомства с кабинетом. Все демо-строки помечены флагом и при первой успешной синхронизации с Метрикой удаляются автоматически; пока они есть, в кабинете показывается плашка «Демо-данные».

## UTM-покрытие

**Формула.** UTM-покрытие = визиты с заполненными utm_source / utm_medium / все визиты × 100 %.

**Где смотреть.** «Трафик → UTM» против общего числа визитов на «Обзоре».

**Интерпретация.** Низкое покрытие (много «(none)») означает прямые заходы и неразмеченные кампании. Для честного сравнения кампаний добивайтесь разметки всех платных каналов.

## Кейсы

- **«Сравнить две кампании честно»** — берите конверсию и отказы, а не только визиты: кампания с меньшим трафиком, но большей конверсией, эффективнее.
- **«Директор спросил "сколько людей было"»** — назовите посетителей за период (не сумму по дням) и уточните, что это уникальные браузеры, а не люди.
- **«Оценить новую рекламу»** — проверьте UTM-покрытие: если кампания не размечена, оценить её по данным нельзя.

## Частые проблемы

| Проблема                                            | Причина и решение                                                                                   |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Сумма посетителей по дням больше значения за период | Норма: уникальность считается на всём периоде.                                                      |
| «Средние» отказы посчитаны неверно                  | Считайте средневзвешенное по визитам.                                                               |
| Цифры ≠ интерфейсу Метрики                          | Сверяйте период; Метрика иногда доуточняет данные задним числом — после синка расхождения исчезают. |
| Конверсия «упала», хотя целей больше                | Росли визиты быстрее целей — смотрите оба числа, а не только процент.                               |
