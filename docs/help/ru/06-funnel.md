# Воронка конверсии

## Что показывает

Воронка строится от общего числа визитов к достижениям основной цели. Для каждого этапа видна абсолютная величина и конверсия к предыдущему шагу. Страница /app/funnel считает по дневным данным из базы — она отражает устоявшуюся картину за период (7/30/90 дней), а не сиюминутное состояние.

![Скриншот: воронка](/screenshots/10-funnel.png)
_Воронка конверсии: этапы с абсолютами и конверсиями; самый узкий этап — кандидат на оптимизацию._

## Как анализировать

1. Найдите этап с минимальной конверсией к предыдущему шагу — это самое узкое место.
2. Сравните его абсолют с прошлым периодом: изменилось количество или конверсия?
3. Откройте «Поведение → Страницы выхода» для контекста — где именно уходят люди.
4. Сформулируйте гипотезу в «Отчёт» и проверьте эффект после правок на сайте.

## Этапы и типичные проблемы

| Этап              | Что считается         | Типичное узкое место            |
| ----------------- | --------------------- | ------------------------------- |
| Визиты            | Все визиты периода    | Реклама ведёт не на ту страницу |
| Интерес (глубина) | Визиты с вовлечением  | Контент лендинга не удерживает  |
| Начало оформления | Переход к регистрации | CTA не видно на мобильном       |
| Достижение цели   | Основная цель (KPI)   | Форма, оплата, доверие          |

## Данные и границы

Воронка считается по дневным данным из базы после синка. Для данных за сегодня используйте «Live → Воронка live» (/app/funnel-live) — она считает по событиям билетной воронки pc-goals за текущий день. Синк проходит каждые 3 часа, поэтому «вчерашний» день в периодической воронке появляется с небольшим запаздыванием — это ожидаемое поведение, а не ошибка.

Различие двух воронок: /app/funnel — период и общая конверсия «визит → цель»; /app/funnel-live — детальные шаги покупки билета за сегодня (от показа тарифов до оставленных контактов). Для еженедельных отчётов берите первую, для оперативного мониторинга — вторую.

## Пример чтения

Конверсия «оформление → цель» равна 40 % при 500 визитах: до оформления доходит 50 человек, целевых действий 20. Проблема не в объёме трафика, а в шаге оформления — начинать следует с формы, а не с рекламы. Правило простое: сначала найдите худший переход, потом ищите его причину на сайте.

Числа в примере условные, но порядок рассуждения всегда один: абсолют → конверсия шага → сравнение с прошлым периодом → гипотеза.

## Кейсы

- **«После редизайна упала конверсия»** — постройте воронку за 7 дней до и после релиза (переключатель периода), найдите просевший этап, зафиксируйте гипотезу и следите за ней.
- **«Куда вкладывать следующий месяц»** — узкое место на первом этапе (визиты → интерес) — работайте с трафиком и контентом; в конце (оформление → цель) — с формой и оплатой.
- **«Воронка для планёрки»** — период 30 дней, скриншот воронки + одно предложение про самый узкий этап; детали — в карточке цели.

## Частые проблемы

| Проблема                         | Причина и решение                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------------- |
| Сегодняшнего дня нет             | Дневные данные приходят синком каждые 3 часа — смотрите Live-воронку.                              |
| Конверсия этапа больше 100 %     | Этапы считаются по разным визитам (несессионная воронка) — опирайтесь на абсолюты.                 |
| Воронка пустая                   | Нет данных за период — проверьте синк и выбранный период.                                          |
| Этапы не бьются с карточкой цели | Воронка отражает путь ко всем достижениям KPI, карточка — по одной цели; периоды должны совпадать. |
| Нужна строгая сессионная воронка | Кабинетные воронки обзорные; точный пошаговый учёт внутри сессий делается в Метрике сегментами.    |

## Источник данных и границы

Периодическая воронка агрегирует дневные данные (`channel_stats` по основной цели +
`b2b_manual` + `b2c_payments`) — она «застывает» после синка и отражает устоявшийся период.
Live-воронка (`/app/funnel-live`) читает события билетной воронки pc-goals через Reporting API
на лету и показывает рег-шаги: открытие регистрации → корзина → шаг регистрации → оплата.
Стадии подписаны и окрашены; источник значения каждой стадии указан (visits/goal/manual).

## Чтение воронки B2C и B2B

Воронка кабинета показывает две ветки: B2C (визит → заявка по цели) и B2B (пайплайн сделок).
Колонка «Оплачено B2B» — только стадия `paid`; переговоры и счета — ниже, в пайплайне B2B
(страница «B2B-сделки»). Правило «заявка ≠ оплата» соблюдено и здесь: заявки не складываются
с оплаченными билетами.
