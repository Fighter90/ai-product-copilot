# История и B2B

## История

Страница «История» (/app/history) показывает дневные ряды из базы: визиты, цели, синхронизации. Полезно для проверки «что было синкнуто и когда» и для сравнения любых дат — вплоть до первого синка.

![Скриншот: история](/screenshots/14-history.png)
_История: дневные ряды визитов и целей, отметки о синхронизациях._

Workflow «сверить день с Метрикой»:

1. Найдите нужную дату в таблице «История».
2. Сравните визиты и цели с интерфейсом Метрики за ту же дату.
3. Если день пустой — синк за него не выполнялся; запустите вручную «Админ → Яндекс.Метрика → Синк».
4. После синка вернитесь и убедитесь, что день заполнен.

## Синхронизации

Каждый синк фиксируется: период, объём, статус. Плановые синки проходят по расписанию сервера каждые 3 часа, ручные запускаются администратором из админки. По журналу синков видно, насколько свежи данные на конкретную дату — это первый шаг при любом разборе «почему цифры не сходятся».

## B2B

Раздел «B2B» (/app/b2b) ведёт сделки по партнёрским и корпоративным продажам: этапы, суммы, даты оплат. Сделки создаются кнопкой «Добавить», этап меняется выбором из списка. Данные хранятся в той же базе и не зависят от Метрики — это ручной реестр, который ведут аналитики.

![Скриншот: b2b](/screenshots/15-b2b.png)
_B2B-сделки: компании, билеты, этапы, суммы и даты оплат в одной таблице._

## Поля сделки

| Поле            | Назначение                                                |
| --------------- | --------------------------------------------------------- |
| Компания        | Название партнёра или заказчика                           |
| Билеты          | Количество билетов в сделке                               |
| Этап            | Стадия: переговоры, счёт, оплата и т.д. (выбор из списка) |
| Сумма, ₽        | Итоговая стоимость сделки                                 |
| Дата добавления | Когда сделка заведена в реестр                            |
| Дата оплаты     | Когда пришли деньги                                       |

Сделки B2B выгружаются в DataLens отдельным датасетом `b2b_deals` — удобно строить воронку продаж и следить за выполнением плана вне кабинета.

## Кейсы

- **«Партнёр просит подтвердить оплату»** — найдите сделку в «B2B», проверьте «Дата оплаты» и сумму; при необходимости выгрузите CSV.
- **«Свести итоги по B2B за месяц»** — отсортируйте по дате добавления, просуммируйте колонку «Сумма» или выгрузите CSV и посчитайте в таблице.
- **«Сравнить онлайн и B2B»** — цели билетной воронки на «Live» против сумм сделок в «B2B» — два канала продаж в одном кабинете.

## Частые проблемы

| Проблема                           | Причина и решение                                                                   |
| ---------------------------------- | ----------------------------------------------------------------------------------- |
| День в «Истории» пустой            | Синк за тот день не выполнялся — запустите вручную, данные дозаполнятся из Метрики. |
| Сделка удалена случайно            | Удаление фиксируется в аудите; восстановление ручное — обратитесь к администратору. |
| Суммы B2B не бьются с бухгалтерией | Кабинет — аналитический реестр; источник истины по деньгам — бухгалтерия.           |
| B2B-данных нет в Live              | Реестр ручной и не связан с Метрикой — смотрите страницу «B2B» и датасет b2b_deals. |

## История отчётов

Каждая сборка отчёта сохраняет снапшот (период, дата, размер) — из истории можно открыть
предпросмотр, выгрузить DOCX/PDF ещё раз или удалить срез. Снапшот неизменяем: пересборка
создаёт новый. Это защита от «цифры поменялись после того, как отчёт отправили».

## B2B-сделки

Реестр ручного ввода: Метрика B2B не видит, поэтому сделки ведутся здесь (таблица
`b2b_manual`). Колонки: компания, билеты, сумма, стадия (Лид → Переговоры → Счёт выставлен →
Оплачено), даты добавления и оплаты, контакт. Оплаченные билеты входят в KPI «300 платных» и в
строку «оплат» маркетинговой сетки.

### Импорт истории из CSV

Кнопка импорта принимает CSV `company,tickets,stage,date_added[,date_paid[,amount,email,notes]]`
— для переноса сделок из CRM/таблиц за период до запуска кабинета. Дубликаты (та же компания +
дата + билеты) пропускаются — повторный импорт безопасен. Ошибки строк показываются с номерами.

### Покрытие данных

Индикатор покрытия показывает первые/последние даты рядов (b2b, b2c, Метрика) и дыры ≥ 3 дней
— закрывайте их импортом или синком окна, чтобы KPI и прогноз считались по полному периоду.
