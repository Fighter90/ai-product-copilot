# Как строятся отчёты

Отчёт — это не «скриншот дашборда», а отдельный неизменяемый документ. Ниже — весь путь данных по шагам и инструкция, что нажимать на странице «Отчёт» (`/app/report`).

## Конвейер в одном взгляде

| Шаг | Что происходит                                       | Где живут данные                    | Участвует AI |
| --- | ---------------------------------------------------- | ----------------------------------- | ------------ |
| 1   | Синк Метрики → SQLite                                | `raw_responses` + таблицы-агрегаты  | нет          |
| 2   | Срез данных (snapshot) за период                     | `report_snapshots`, JSON-payload    | нет          |
| 3   | Графики (3 PNG) и блоки 🟢/🔴                        | рендерятся из снапшота при экспорте | нет          |
| 4   | Документ DOCX по ГОСТ Р 7.32-2017                    | собирается из снапшота              | нет          |
| 5   | PDF через headless Chrome                            | собирается из того же снапшота      | нет          |
| 6   | AI-анализ, AI-гипотезы, предложения в Decision Log   | дописываются в тот же снапшот       | да           |
| 7   | Проверка оформления `scripts/verify-report-gost.mjs` | готовый DOCX                        | нет          |

Главное правило: шаги 3–5 не обращаются ни к Метрике, ни к AI — только к сохранённому снапшоту. Поэтому цифры на экране, в DOCX и в PDF совпадают.

## Шаг 1. Синк Метрики в SQLite

- Синк запрашивает у Метрики (Stat API) агрегаты по дням: каналы, UTM-метки, гео и устройства, страницы входа и выхода, цели.
- Каждый сырой ответ Метрики сохраняется в таблицу `raw_responses` — это **источник фактов**. Из него строятся агрегаты `channel_stats`, `utm_stats`, `geo_device_stats`, `page_stats`, `exit_page_stats`.
- На сервере синк идёт автоматически каждые 30 минут (systemd-таймер `pca-sync.timer`). Вручную — кнопка «Обновить данные из Метрики» в «Администрирование → Метрика и данные» (только администратор).
- Роботы и служебные визиты по умолчанию отфильтрованы.

Если за период синка не было, отчёт будет пустым: в блоке рекомендаций появится «Нет данных по каналам за период — синхронизируйте данные из Метрики».

## Шаг 2. Срез данных (snapshot)

Кнопка «Сформировать срез данных» собирает снапшот за период из глобального фильтра. Срез читает **только локальную базу** (никаких живых запросов к Метрике) и замораживает:

- **KPI** — цель 300 оплаченных билетов, заявки B2C (сумма достижений основной цели), оплаченные B2B-билеты и Gap до цели. Если основная цель — покупка, её достижения тоже идут в зачёт оплат;
- **каналы** — визиты, посетители, отказы, достижения цели по каждому каналу;
- **воронку** — визиты → заявки B2C → B2B в работе → оплачено B2B;
- **разрезы** — топ UTM, топ гео и устройств, топ страниц входа и выхода;
- **B2B-сделки** — состояние пайплайна на момент среза (все сделки, без фильтра по датам);
- **гипотезы и Decision Log**, заведённые в базе к этому моменту.

Срезу присваивается уникальный ИД (UUID) и время формирования. Последующие синки **не меняют** уже созданный срез — чтобы увидеть свежие данные, сформируйте новый. AI-тексты (шаг 6) дописываются в тот же срез, но числа в нём при этом не пересчитываются.

## Шаг 3. Графики и светофор 🟢/🔴

При экспорте сервер рисует три графика из чисел снапшота: ECharts запускается в headless Chrome, анимация выключена, результат — PNG.

| Рисунок                          | Тип            | Что показывает                                        |
| -------------------------------- | -------------- | ----------------------------------------------------- |
| Визиты и заявки по каналам       | столбцы        | две серии на канал — видно, какой трафик конвертирует |
| Воронка: визит → заявка → оплата | воронка        | визиты → заявки B2C → B2B в работе → оплачено B2B     |
| Доля каналов по визитам          | кольцо (donut) | структура трафика и зависимость от одного источника   |

Картинки рендерятся один раз на выгрузку и одинаковыми вставляются в документ. Если на сервере не найден Chrome, отчёт всё равно соберётся — без рисунков, текстом и таблицами.

Под каждым рисунком — блок «🟢 Что хорошо / 🔴 Что плохо». Он считается **по порогам, без AI**:

| Порог                       | Значение | Как применяется                                             |
| --------------------------- | -------- | ----------------------------------------------------------- |
| Хорошая конверсия           | ≥ 5%     | лучший канал с CR ≥ 5% — «масштабировать»                   |
| Плохая конверсия            | < 2%     | худший канал или общая воронка ниже 2% — «проверить трафик» |
| Минимум визитов для сигнала | 50       | каналы с меньшим трафиком в сравнении не участвуют          |
| Зависимость от канала       | ≥ 70%    | если топ-канал даёт ≥ 70% визитов — риск одного источника   |
| Отказы страницы входа       | ≥ 70%    | страница попадает в «что плохо» общего блока рекомендаций   |

Для воронки дополнительно показывается, достигнута ли цель 300 и сколько оплат не хватает. Если по порогам ничего не выявлено, пишется нейтральная фраза «Явных сильных сторон / проблем по порогам не выявлено».

## Шаг 4. Структура DOCX по ГОСТ Р 7.32-2017

Порядок разделов документа:

1. **Титульный лист** — всё по центру: строка трека, «АНАЛИТИЧЕСКИЙ ОТЧЁТ», период, источники, год. ИД среза на титуле не печатается — он в приложении.
2. **СОДЕРЖАНИЕ** — настоящее поле оглавления Word с гиперссылками (уровни заголовков 1–2). Номера страниц появляются после обновления полей (Word обычно предлагает это при открытии; вручную — F9).
3. **ПЕРЕЧЕНЬ РИСУНКОВ** — подписи всех рисунков («Рисунок N — …»), те же, что под картинками.
4. **ОБОЗНАЧЕНИЯ, ТЕРМИНЫ И СОКРАЩЕНИЯ**, **ВВЕДЕНИЕ**, **УПРАВЛЕНЧЕСКОЕ РЕЗЮМЕ** — без номеров.
5. Нумерованные разделы начиная с **«1. КРАТКИЕ ИТОГИ»**: рекомендации «что хорошо и что плохо», методология, воронка конверсии, B2B-пайплайн, анализ каналов, рисунки воронки и структуры трафика, приоритизация гипотез по ICE, Define / Develop (гипотезы), Deliver (Decision Log), AI-анализ, топ гео и устройств, UTM, страниц входа и выхода, дорожная карта, глоссарий.
6. **Приложения** — заголовки, начинающиеся со слова «Приложение» (например, «Приложение с данными» с ИД среза), не нумеруются.

Пустые разделы («данных нет», «проверок пока нет») автоматически выбрасываются, поэтому число разделов зависит от данных.

Оформление: A4, поля слева 30 мм, справа 15 мм, сверху и снизу 20 мм; Times New Roman 14 pt, межстрочный 1,5, текст по ширине; заголовки чёрные, заглавными, со сквозной нумерацией; все таблицы в рамке; подписи рисунков курсивом 12 pt по центру; номер страницы по центру в нижнем колонтитуле.

## Шаг 5. PDF

PDF собирается из того же снапшота: сервер формирует HTML-версию отчёта и печатает её в A4 через headless Chrome. Путь к Chrome определяется автоматически (macOS, Linux, Windows) или задаётся переменной `PUPPETEER_EXECUTABLE_PATH`. Без Chrome PDF не соберётся — используйте DOCX (он от Chrome не зависит, кроме рисунков).

## Шаг 6. AI-анализ, гипотезы и Decision Log

AI подключается только через провайдеров, настроенных администратором («Администрирование → AI-провайдеры»). Провайдеры обходятся по приоритету; если один отказал, запрос автоматически уходит следующему.

**AI-анализ (insights).** Кнопка «Сгенерировать AI-анализ» запускает 6 последовательных запросов — по одному на раздел: Итог · Каналы, UTM и Аудитория · Страницы и Воронка · Риски и Рекомендации · Гипотезы и Дорожная карта · Итоговый вывод. Обычно это 5–10 минут; на каждый раздел — до 2 минут. Если раздел не удался, вместо него будет пометка «Ошибка генерации… — раздел пропущен», остальные сохранятся. Готовый текст записывается в снапшот, кнопка становится неактивной («AI-анализ сгенерирован»).

**AI-гипотезы.** Генерируются автоматически в фоне сразу после формирования среза, если доступен хотя бы один провайдер:

- **10 гипотез проблем** по формуле «[сегмент] испытывает [проблему] при [действии], потому что [барьер]», у каждой — ссылка на конкретное число из среза;
- **10 гипотез решений** «Если [действие], то [польза], что приведёт к [результату]» — с критерием успеха, пятью рисками (ценность, удобство, реализуемость, бизнес, право), планом проверки (минимум 2 метода), светофором 🟢/🟡/🔴 и дедлайном;
- **ICE** — модель ставит только Impact, Confidence и Ease (1–10) с обоснованиями. Итоговый балл **считается в коде**: Impact × Confidence × Ease (произведение, шкала 1–1000). Число, которое могла бы предложить модель, игнорируется;
- **Decision Log** — после гипотез модель предлагает не менее 3 записей журнала решений (метод, период, выводы, исход green / yellow / red).

Генерация идёт в фоне, поэтому сразу после формирования среза счётчик «AI-гипотез» может показывать «не сгенерированы». Через несколько минут откройте этот срез из «Истории» — гипотезы и решения подтянутся. Если генерация не удалась, нажмите «Перестроить отчёт»: будет создан новый срез и новая попытка.

**Защита от галлюцинаций.** Модель получает только текстовую выжимку чисел из снапшота — не сырые визиты и не персональные данные. В инструкции модели прямо запрещено выдумывать цифры и смешивать заявки с оплатами; ответ гипотез обязан быть строгим JSON и проверяется по схеме. Графики, светофоры и ICE-балл AI не трогает. AI-разделы в документе — интерпретация: каждую цифру сверяйте с таблицами.

## Шаг 7. Проверка оформления DOCX

Для контроля ГОСТ есть скрипт без внешних зависимостей (нужен системный `unzip`). Запуск из корня репозитория: `node scripts/verify-report-gost.mjs путь/к/отчёту.docx`.

Что проверяется: поля страницы, формат A4, Times New Roman и 14 pt по умолчанию, межстрочный 1,5, отсутствие синих заголовков Word, поле номера страницы в колонтитуле, рамки таблиц, подписи «Рисунок N», обязательные разделы (СОДЕРЖАНИЕ, ПЕРЕЧЕНЬ РИСУНКОВ при наличии рисунков, УПРАВЛЕНЧЕСКОЕ РЕЗЮМЕ, ВВЕДЕНИЕ, ОБОЗНАЧЕНИЯ).

Итог — `VERDICT: PASS`, `PASS-WITH-WARNINGS` или `FAIL`; код выхода 0 для первых двух и 1 для FAIL.

## Пошагово на странице «Отчёт»

1. Выберите период в фильтре вверху (7д / 14д / 30д / 90д / 1г или свои даты). Для отчёта берите осмысленный интервал — неделю или месяц.
2. Нажмите **«Сформировать срез данных»**. Появятся ИД среза, период, KPI-полоса (Цель, заявки или заказы по основной цели, «Заказов создано (B2B)», Gap), сводка воронки, B2B-пайплайн и полный отчёт на экране.
3. Подождите фоновые AI-гипотезы (если провайдер настроен) — затем откройте срез из «Истории», чтобы увидеть их.
4. По желанию нажмите **«Сгенерировать AI-анализ»** и дождитесь прогресс-бара (5–10 минут). Страницу можно не обновлять.
5. Нажмите **«Export DOCX»** или **«Export PDF»** — файл `productcamp-report-<ИД>.docx` / `.pdf` скачается на компьютер. Графики рендерятся в момент выгрузки, поэтому первая выгрузка занимает несколько секунд.
6. Откройте DOCX в Word и обновите поля (F9), чтобы в «Содержании» появились номера страниц.
7. Нужен отчёт с новыми данными или фильтрами — **«Перестроить отчёт»** создаст новый срез. Старый останется в «Истории».

Если вы пришли со страницы «Обзор» или «Трафик» по ссылке «→ гипотеза», вверху появится «Черновик гипотезы» с полями ЦА, проблема, действие, барьер, данные. Черновик хранится в браузере до конца сессии; кнопка «Убрать черновик» его удаляет.

## Частые вопросы

| Вопрос                                          | Ответ                                                                                            |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Почему в отчёте не те цифры, что сейчас в Live? | Live — живые данные Метрики за сегодня, отчёт — замороженный срез из SQLite за выбранный период. |
| В DOCX нет рисунков                             | На сервере не найден Chrome — администратор задаёт `PUPPETEER_EXECUTABLE_PATH`.                  |
| В «Содержании» нет номеров страниц              | Обновите поля в Word (F9 или согласитесь на обновление при открытии).                            |
| «AI-анализ недоступен»                          | Нет включённого провайдера с ключом — см. статью «Ключи LLM-провайдеров» (`/help/llm-keys`).     |
| Гипотезы не появились                           | Откройте срез из «Истории» через несколько минут; если пусто — «Перестроить отчёт».              |
| Можно ли поправить цифры в срезе?               | Нет, срез неизменяем по замыслу. Исправьте данные (синк, B2B-сделки) и сформируйте новый срез.   |
