# ADR-014 — Порог покрытия 75% вместо 100%

- **Статус:** принято (заменяет ADR-006 в части порогов покрытия)
- **Дата:** 2026-10-27
- **Задача:** [ANA-26](https://linear.app/analitics-platform/issue/ANA-26)

## Контекст

ADR-006 (§ «Покрытие») фиксирует **100%** порог v8-покрытия (lines/functions/branches/statements).
На практике при масштабе v3 (кабинет, роли, AI-провайдеры, отчёты, DataLens) это:

- тормозит итерации: любая нетривиальная правка требует «догонять» 100% на
  нетестируемой обвязке (генерируемый код, клей мутаций, обёртки ECharts и т.п.);
- стимулирует исключения: в `vitest.config.ts` уже накопились `exclude`-строки
  (ai-insights, chart-renderer, overview.tsx, funnel.tsx …) — то есть порог 100% давно
  поддерживается не строго, а выборочным исключением, что скрывает реальную картину.

## Решение

Снизить порог до **75%** по lines / functions / branches / statements:

- `code/backend/vitest.config.ts` — 75%;
- `code/shared/vitest.config.ts` — 75%;
- `code/frontend/vitest.config.ts` — 75%.

`pnpm coverage` гоняет `vitest run --coverage` во всех трёх пакетах и в CI: падение
сборки ниже порога ломает job. «Основной функционал» обязателен к покрытию независимо от
порога: auth/RBAC, Metrika-клиент и синк, агрегаторы KPI, отчёт (snapshot, DOCX/PDF),
AI-провайдеры (с моками HTTP), гипотезы.

Исключения из покрытия остаются регламентированными в `exclude` (bootstrap/entry,
Puppeteer-рендер графиков, e2e-only обёртки).

## Последствия

- ✅ Итерации быстрее; `exclude`-список можно постепенно сокращать.
- ⚠️ На изменённых модулях خارج «обязательного списка» покрытие может быть ниже
  100% — это приемлемо по AR-014; реальный контроль качества — модель тестов из ADR-006
  (пирамида unit / integration / e2e пе скрывается).
