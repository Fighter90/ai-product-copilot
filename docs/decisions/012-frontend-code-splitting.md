# ADR-012 — Ленивая загрузка маршрутов кабинета (React.lazy)

- **Статус:** принято
- **Дата:** 2026-10-26
- **Контекст:** после v3-кабинета весь фронтенд собирался в один чанк: главный бандл 406KB
  (gzip 125) — включая страницы, доступные только после входа. Первый экран (лендинг) грузил
  571KB JS, хотя публичному посетителю кабинет не нужен. Роутинг — `react-router-dom` v6,
  сборщик — Vite/Rollup (нативная поддержка динамических импортов).

## Решение

- **React.lazy + `import()` для всех 19 маршрутов `/app/*`** (обзор, трафик, поведение,
  воронка, KPI, отчёт, история, B2B, Live, Goals, GoalDetail, FunnelLive, Explore, DataLens
  и 5 страниц админки). Каждый маршрут — свой чанк, грузится при первом переходе.
- **Публичные страницы и Assistant остаются в главном бандле**: Landing, Login, HelpCenter —
  это первый экран, Assistant (плавающая панель) нужен почти на каждом экране — отдельный чанк
  ничего бы не сэкономил, а добавил бы водопад запросов.
- **`<Suspense fallback={<RouteFallback />}>`** обёртывает всё дерево маршрутов; фолбэк повторяет
  вид Splash из auth (центрированный спиннер на фоне `bg-canvas`) — переход выглядит как
  «система открывается», а не как мигание контента.
- Модули маршрутов используют именованные экспорты — обёртка
  `.then((m) => ({ default: m.X }))` приводит их к контракту `React.lazy` (дефолтному экспорту).

## Обоснование

- Кабинет — приложение для одного пользователя на сессию: он открывает 3–5 страниц из 19.
  Грузить все 19 при первом визите — трата против паттерна «плати за то, что посетил».
- Публичные маршруты — только 4, выделение их в чанки не окупает накладных расходов и
  усложняет первый экран (водопад: HTML → main → landing).
- Vite/Rollup сам поднимает **общие чанки** для кода, на который ссылаются ≥2 ленивых маршрута
  (DataGrid, диалоги) — ручное управление общим кодом не нужно.

## Последствия

- Главный чанк **149KB (gzip 47, −63% от 406KB)**; чанки маршрутов — **по 1–36KB** на страницу;
  JS первого экрана — **313KB** (свой + лендинг + Assistant).
- При **первой** навигации на маршрут виден Suspense-фолбэк (спиннер) — задержка на локальном
  деплое незаметна, на медленной сети это честный индикатор загрузки. Повторные переходы
  мгновенны (чанк закэширован браузером).
- Общий чанк DataGrid/диалогов выделяется сборщиком автоматически; его состав не фиксируем —
  при смене зависимостей он может перекроиться, на интерфейс это не влияет.
- Ошибки загрузки чанка (офлайн, деплой в момент навигации) ловит общий `ErrorBoundary`
  вокруг дерева маршрутов — отдельный retry-механизм не вводим.

## Альтернативы

- **Оставить один бандл** — отклонено: 571KB JS на первый экран недопустимы для лендинга.
- **Разбивка по ролям (кабинет/админка двумя чанками)** — отклонено: слишком крупно, чанк
  кабинета всё равно оказался бы в сотни килобайт; постраничная разбивка даёт чанки 1–36KB.
- **Ручная настройка `manualChunks`** — отклонено: Rollup сам выделяет общие модули корректно,
  ручная карта чанков — лишний код, который надо поддерживать при каждом рефакторинге.
