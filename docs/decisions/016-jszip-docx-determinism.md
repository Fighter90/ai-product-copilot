# ADR-016 — Прямая зависимость `jszip` (детерминированный DOCX-реэкспорт)

- **Статус:** принято
- **Дата:** 2026-11-16
- **Контекст:** ANA-188 — повторный экспорт DOCX того же `snapshotId` давал другой файл
  (wall-clock штампы zip-записей, `dcterms:created/modified`, «плавающие» закладки `_TocN`,
  `wp:docPr id`). Фикс (`code/backend/src/report/docx/determinize.ts`) перепаковывает
  Packer-буфер через JSZip с зафиксированными датами/опциями. По `CLAUDE.md` зависимость вне
  зафиксированного стека добавляется только через ADR; `jszip` к тому же критична для
  инварианта «один snapshotId → байт-идентичный файл», поэтому обязана быть **прямой**
  (не hoisted-транзитивкой от `docx`) и **запиненной** по версии.

## Решение

Объявить **`jszip` `3.10.2`** (точная версия, без `^`) как runtime-зависимость
`code/backend` и использовать её для детерминированной перепаковки DOCX в
`determinizeDocx`. Тот же `3.10.2` резолвится и для `docx@9` (его диапазон `^3.10.1`),
то есть в дереве один экземпляр библиотеки.

## Обоснование

- **Детерминизм зависит от версии перепаковщика.** Байты zip (DEFLATE-поток, порядок и
  формат локальных заголовков) определяются реализацией JSZip; минорный релиз может
  изменить побайтовый вывод. Точный пин `3.10.2` делает «та же (content, dates) → те же
  байты» свойством зафиксированной версии, а не надеждой на диапазон `^`.
- **Прямое объявление устраняет латентный разрыв.** При pnpm strict layout импорт
  транзитивной зависимости — ошибка резолва; обновление/замена `docx` могло бы молча
  убрать `jszip` из дерева.
- **Альтернативы отклонены:** распаковывать/перепаковывать OOXML голым Node API (нет
  встроенной поддержки zip) или форкать `docx` ради опций Packer — несоизмеримо дороже;
  добавлять опцию даты в сам `docx` — внешний контрибьюторский путь вне наших сроков.

## Последствия

- `determinizeDocx` — единственный production-потребитель `jszip` в бэкенде (тесты —
  `tests/report/docx-xml.ts`, `docx.test.ts`).
- Обновление `jszip` теперь требует осознанной правки пина + прогон байт-идентичного
  теста (`docx.test.ts`, describe «ANA-188 deterministic re-export»).
- Пин относится только к бэкенду; фронтенд `jszip` не использует.
