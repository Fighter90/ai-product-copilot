# Troubleshooting — устранение неполадок

> Версия: v3.4.64 (18.11.2026). 🇷🇺 Русский (зеркало: [docs/en/troubleshooting.md](en/troubleshooting.md)).
> Формат: **Симптом → Причина → Решение**. Если решения нет — завести issue в Linear (команда ANA).

---

## 1. Вход и доступ

### 1.1 «Неверный email или пароль»

- **Причины**: опечатка; пароль ротирован; капс/раскладка.
- **Решение**: проверьте креды у администратора; после 5 неудач — временная блокировка, подождите. Админ может сбросить пароль (админка → Пользователи → «Сбросить пароль»).

### 1.2 «Нет доступа» на прямом URL (`/app/admin/...` у аналитика)

- **Причина**: RBAC — админка только для роли Администратор.
- **Решение**: штатно. Нужен доступ — попросите админа сменить роль.

### 1.3 После «Выйти» кнопка «Назад» на секунду показывает кабинет

- **Причина**: bfcache браузера отдаёт устаревший шелл из кэша.
- **Решение**: обновите страницу (F5) — данные не утечут (сессия отозвана, API отвечает 401). Если шелл висит дольше 2–3 секунд — сообщите (backlog ANA-197).

### 1.4 Онбординг-тур показывается повторно

- **Причина**: тур показывается один раз после входа; повтор при смене языка в модалке профиля — известная мелочь (backlog ANA-197).
- **Решение**: «Пропустить тур». Если тур на каждый reload — баг, заведите issue.

### 1.5 Язык/тема слетели

- **Причина**: очистка localStorage (приватный режим, очистка данных сайта).
- **Решение**: переключить RU/EN и тему заново — выбор сохранится.

## 2. Данные и синхронизация

### 2.1 Обзор пустой / «0 визитов» там, где должны быть данные

- **Причины**: sync не выполнялся за период; период фильтра вне диапазона данных; выбран сегмент B2B (плитки цели скрыты — это норма).
- **Решение**: проверить период (14д по умолчанию); убедиться, что ночной sync отработал (админ: `/opt/pca/data`, таблица `sync_runs`); запустить sync (`pnpm sync` / scheduler).

### 2.2 Sync падает

- **Причины**: истёк `METRIKA_OAUTH_TOKEN`; квоты Reporting API; недоступность API.
- **Решение**: админ → Метрика → проверка токена; обновить токен (OAuth); при квотах — дождаться окна/уменьшить частоту; лог ошибок в `sync_runs` и `raw_responses` (статусы).

### 2.3 UTM-таблица: много `(none)`

- **Причина**: прямой/неразмеченный трафик; покрытие UTM ~31–32% — норма для этого кемпа.
- **Решение**: улучшать разметку кампаний (utm_source/medium/campaign обязательны во всех ссылках).

### 2.4 Цифры Обзора и воронки различаются

- **Не должно случаться**: оба используют единый `periodTotals`. Если различие >0% — баг, заводить issue с периодом и скринами.

### 2.5 Воронка pc-goals: не видна ступень «Оплата»

- **Причина**: в счётчике нет цели оплаты (`source: none`) — «Оплата» берётся из B2B-оплат за период (fallback).
- **Решение**: завести цель оплаты в Метрике или пользоваться B2B-вводом.

### 2.6 Плитки «ЦЕЛЬ/ОСТАЛОСЬ ДО ЦЕЛИ» исчезли

- **Причина**: выбран сегмент **B2B** — цели Метрики относятся к общему потоку, в B2B их нет.
- **Решение**: вернуть сегмент `B2C+B2B`. Пояснение на месте плиток — штатное поведение.

## 3. Отчёты и экспорт

### 3.1 Кнопки Export показывают «Готовим…» долго (>30 с)

- **Причина**: PDF рендерится серверным Chrome — 12–20 с штатно; при нескольких параллельных запросах дольше.
- **Решение**: дождаться; повторные клики невозможны (кнопки disabled). Если >60 с и ошибка в ErrorBox — смотреть раздел 3.3.

### 3.2 Экспорт не скачивается / файла нет

- **Причины**: браузер блокирует загрузки; переполнение диска; падение рендера.
- **Решение**: проверьте папку загрузок; повторите один раз; ошибка появится в ErrorBox над превью (текст HTTP-статуса). Систематически повторяется — issue с `snapshotId`.

### 3.3 DOCX/PDF двух скачиваний различаются байтами

- **Не должно случаться**: детерминизм покрыт тестами (даты прошиты из снапшота). Единственное известное исключение — **первый PDF-рендер после рестарта сервера** (холодные шрифты).
- **Решение**: скачайте второй раз — второй и последующие файлы идентичны. Стабильное воспроизведение — issue.

### 3.4 «The report behind this link was not found…»

- **Причина**: `?snapshot=<id>` указывает на удалённый/невалидный снапшот.
- **Решение**: перейти в **Историю** (ссылка в баннере) и выбрать нужный снапшот или собрать новый.

### 3.5 В отчёте нет секции «Маркетинг»

- **Причина**: период не пересекает ни одной заполненной недели партнёров (`marketing_weekly`).
- **Решение**: собрать отчёт за период, пересекающий заполненные недели (например, 30д), либо заполнить сетку на странице Маркетинг.

### 3.6 AI-анализ: «провайдер недоступен» / poor quality

- **Причины**: все провайдеры в цепочке исключены (баланс/ключ); LLM недоступна.
- **Решение** (админ): админка → AI-провайдеры → проверка связи, включить живого (OpenRouter 372 вызова/30д — эталон работы), обновить ключ. Низкое качество — уточнить период/язык, повторить (каждый вызов логируется в `ai_usage`).

## 4. Гипотезы и решения

### 4.1 «Сохранить» заблокировано в гипотезе

- **Причина**: blockers-панель перечисляет недостающее (≥3 допущений, ≥2 методов, светофор, дедлайн, формат).
- **Решение**: заполнить пункты панели; пустые строки допущений/методов мешать не должны (если мешают — баг).

### 4.2 Решение не сохраняется

- **Причины**: не выбрана гипотеза; нет даты; пустое «Решение»; нет evidence (цитата+источник); пустое обоснование исхода.
- **Примечание**: выводы (findings) — НЕобязательные: пустые строки отбрасываются и не блокируют (ANA-198/63).

### 4.3 Гипотеза сама уехала в «Просрочена»

- **Причина**: дедлайн прошёл при нетерминальном статусе — автоматический переход.
- **Решение**: открыть карточку → переосмыслить (закрыть/переформулировать/перенести дедлайн через «Редактировать»).

## 5. B2B-сделки

### 5.1 «Билетов: целое число не меньше 1»

- **Причина**: отрицательное/нулевое/дробное число билетов.
- **Решение**: введите целое ≥1. Сумма — произвольная неотрицательная.

### 5.2 Не могу удалить сделку из канбана

- **Причина**: удаление доступно только во вкладке «Таблица».
- **Решение**: Таблица → строка сделки → Удалить → confirm.

### 5.3 Оплаты B2B не появились в KPI

- **Причина**: сделка не в стадии «paid» (или tickets=0).
- **Решение**: перетащить сделку в ОПЛАТА (канбан) или сменить стадию в таблице; обновить KPI.

## 6. Инфраструктура (для админа)

### 6.1 `/api/health` не отвечает / 502

- **Причины**: `pca-api` упал; nginx не может достучаться.
- **Решение**: `systemctl status pca-api` → `journalctl -u pca-api -f` → устранить (диск полон? БД залочена?) → `systemctl restart pca-api` → health.

### 6.2 Health отдаёт старую версию после деплоя

- **Причины**: rsync не докатился; рестарт не произошёл; гейт не выполнен.
- **Решение**: повторить `SSH_KEY=~/.ssh/pca_deploy ./deploy/deploy.sh` — деплой считается успешным только при health = версии сборки.

### 6.3 Бэкапы не создаются

- **Проверка**: `ls -lt /opt/pca/backups | head`; лог `backups/backup.log`; статус timer (`systemctl list-timers`).
- **Решение**: устранить причину из лога (диск, lock-файл); ручной прогон backup.sh.

### 6.4 DataLens: датасеты недоступны

- **Причина**: `DATALENS_IAM_TOKEN` истёк.
- **Решение**: `scripts/refresh-datalens-token.mjs` (нужны `PCA_ADMIN_PASSWORD`, `PCA_SSH_HOST`, локальный `yc`).

### 6.5 Появилась «Новая версия» баннер у всех пользователей

- **Причина**: прод обновился (BuildMismatchBadge сверяет версию сборки UI с API).
- **Решение**: перезагрузить страницу (F5) — баннер уйдёт.

## 7. Полезные проверки

```bash
# health + версия
curl -s https://dashboardcamp.ru/api/health | head -c 200
# статус сервиса и живые логи
systemctl status pca-api && journalctl -u pca-api -f
# свежие бэкапы
ls -lt /opt/pca/backups | head
# байт-идентичность экспортов (curl под сессией)
curl -b cookies.txt -o a.pdf "https://dashboardcamp.ru/api/report/download/<id>/pdf" && \
curl -b cookies.txt -o b.pdf "https://dashboardcamp.ru/api/report/download/<id>/pdf" && \
shasum a.pdf b.pdf
```
