# Сценарии — пошаговые рецепты

> Версия: v3.4.64 (18.11.2026). 🇷🇺 Русский (зеркало: [docs/en/scenarios.md](en/scenarios.md)).
> Пошаговые рабочие сценарии: от утренней проверки до недельного цикла гипотез.

---

## Сценарий 1. Утренняя проверка (5 минут)

**Цель:** понять статус дня без погружения.

1. Войти → **Обзор**.
2. Герой: «Успеваем к 300?» — статус (Успеваем/Не успеваем при текущем темпе), прогноз, темп оплат.
3. Плитки: ВИЗИТОВ / ЗАЯВОК B2C / B2B PIPELINE / ОПЛАЧЕНО B2B — и Δ к прошлому периоду.
4. **Дайджест за неделю** — что изменилось (▼/▲ WoW).
5. **Слабые места** — топ проблем с цифрами.
6. **Сейчас** — что происходит прямо сейчас (если есть активность).

**Результат:** 3 тезиса для утреннего стендапа.

---

## Сценарий 2. Недельный отчёт (10 минут)

**Цель:** отправить команде документированный итог недели.

1. **Отчёт** → период `7д` (или «Даты» на нужные дни) → **Собрать отчёт**.
2. Проверить превью: 17–18 разделов, секция «Маркетинг» (если неделя пересекается), оглавление на месте.
3. **Export DOCX** — дождаться скачивания (имя файла: `productcamp-report-<snapshotId>.docx`).
4. При необходимости **Export PDF** (для почты/мессенджера).
5. **История** — убедиться, что снапшот с бейджем «Текущий» закреплён (план→факт).
6. Отправить файл + ссылку на снапшот (`/app/report?snapshot=<id>`) — получатель откроет тот же отчёт 1-в-1.

**Важно:** файл детерминирован — сколько раз ни скачивай, байты совпадут с отправленным.

## Сценарий 3. Недельный цикл гипотез (Discover → Decide)

**Цель:** от слабых мест до принятых решений.

**Часть A — обнаружение (понедельник):**

1. **Обзор → Слабые места** → выбрать позицию с 🔴 (например, «Прямые заходы 1 774 визитов · CR 0.2%»).
2. **«→ гипотеза»** — форма предзаполнена (subject, title, evidence с цифрой CR и каналом).
3. Дополнить: ЦА, наблюдение, **≥3 допущения** (почему боль есть), **≥2 метода** (например: интервью 5 респондентов + A/B лендинга), светофор (🟢 CR ≥ 2%), дедлайн.
4. Сохранить → карточка в «Черновики».

**Часть B — приоритизация (вторник):** 5. Пройтись по канбану, выставить/проверить **ICE** (I×C×E, произведение). Сортировка сверху — порядок работ.

**Часть C — проверка (ср–чт):** 6. Карточку перевести в **«В проверке»**. Выполнить методы по списку. Зафиксировать цифры.

**Часть D — решение (пятница):** 7. **Решения → Новое решение**: гипотеза, дата, «что делаем», период проверки, разрез, **evidence** (цитата+источник), **исход** 🟢/🟡/🔴 по порогам светофора + обоснование, следующий шаг. 8. Карточка гипотезы → «Подтверждена»/«Частично»/«Отклонена». 9. Итог недели виден: канбан (стадии) + Decision Log (решения с исходами).

## Сценарий 4. Заведение B2B-сделки (2 минуты)

1. **B2B-сделки** → «Новая сделка».
2. Компания («ООО Ромашка»), **билеты** (например, 25; целое ≥1), сумма, дата.
3. Создать → сделка в **ЛИД**.
4. По ходу переговоров перетащить в **ПЕРЕГОВОРЫ** (drag&drop) — плитка «B2B PIPELINE» вырастет на 25.
5. Оплата: перетащить в **ОПЛАТА** → «ОПЛАЧЕНО B2B» +25, KPI и отчёт это учтут.
6. Если сделка не состоялась — удалить во вкладке «Таблица» (confirm).

---

## Сценарий 5. What-if «а если трафик +30%?»

1. **KPI и прогноз** → найти слайдер **«Трафик: ±N%»**.
2. Подвинуть на **+30%**: темп заявок пересчитается (например, 0,8 → 1,0/день), дата цели и «+N дн. (отставание)» обновятся мгновенно.
3. Сравнить с базой: слайдер в 0 возвращает исходный прогноз.
4. **Состояние не сохраняется** — это калькулятор для решений, а не план.

---

## Сценарий 6. Сверка отчёта с Обзором и Метрикой

**Цель:** убедиться, что цифры отчёта = цифры дашборда.

1. Собрать отчёт за период (например, 14д) — записать `snapshotId` из URL.
2. Выписать из превью: визиты, заявки, оплаты B2B, GAP, CR, топ-3 канала.
3. Открыть **Обзор** с тем же периодом — сверить каждую цифру (допуск ±0%: источник один).
4. Спорная цифра? По `query_hash` витрины вернуться к сырому ответу в `raw_responses` (просмотр через админ-API/SQLite).
5. DOCX/PDF: открыть скачанный файл — те же числа (текст из того же снапшота).

## Сценарий 7. Подготовка к дедлайну (за неделю до 21.11)

1. **KPI и прогноз**: зафиксировать «+N дн. (отставание)» и требуемый темп (~75/день при 0 оплат).
2. **Обзор**: HERO-статус → слабые места → все problem-гипотезы с CR-проблемами — в работу этой недели.
3. **B2B-сделки**: пуш по переговорам — каждая сделка в «ОПЛАТА» = билеты в цель.
4. **Маркетинг**: проверить, что недели активаций партнёров заполнены (попадут в отчёт).
5. **Отчёт** за неделю — на координацию; в решениях зафиксировать выводы.
6. Финал: отчёт 30д (секция «Маркетинг» обязательно) + DOCX в архив.

## Сценарий 8. Онбординг нового волонтёра (15 минут)

1. Админ заводит пользователя (роль Аналитик), передаёт временный пароль защищённо.
2. Новичок входит, проходит онбординг-тур (5 шагов), выставляет язык/тему.
3. Читает **Справка** → статьи «Роли и права», «Обзор», «Воронка».
4. Проходит Сценарий 1 (утренняя проверка) с наставником.
5. Домашнее задание: завести одну problem-гипотезу из слабых мест (Сценарий 3, часть A).

---

## Сценарий 9. Проверка детерминизма отчёта (аудит, 3 минуты)

1. **Отчёт** → собрать снапшот.
2. **Export DOCX** ×2 → сравнить размеры/хэши файлов — идентичны.
3. **Export PDF** ×2 → то же (второй рендер; первый после рестарта сервера может отличаться — известная особенность холодных шрифтов).
4. Расхождение стабильно? → issue с `snapshotId` и двумя файлами.

## Сценарий 10. Смена языка интерфейса и отчёта

1. Тумблер **RU/EN** в топбаре — весь кабинет переключается (данные не меняются).
2. Отчёт на EN: собрать/открыть снапшот → **Export DOCX/PDF** при включённом EN → файл получит суффикс `-en` и EN-обвязку.
3. Вернуть RU тем же тумблером.
