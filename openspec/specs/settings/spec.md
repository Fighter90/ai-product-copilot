# settings Specification

> Открытая спека возможности (OpenSpec). Источник истины — код:
> `code/backend/src/settings/app-settings.ts`, `code/backend/src/settings/routes.ts`,
> `code/backend/src/security/crypto.ts`, `code/frontend/src/pages/admin/Metrika.tsx`.
> Обновлена: 2026-10-27.

## Purpose

Настройки приложения хранятся в БД (`app_settings`, key/value) и редактируются из админки:
подключение Метрики (счётчик, OAuth-токен, цели), KPI-цель, ключи провайдеров, токен
DataLens. Секреты шифруются AES-256-GCM мастер-ключом `APP_SECRET`; наружу отдаётся
только маскированный вид с пометкой источника значения.

## Requirements

### Requirement: Хранение настроек в БД

Настройки SHALL храниться в таблице `app_settings`; отсутствие записи означает
незаданное значение, а не ошибку конфигурации.

#### Scenario: Первый запуск без настроек

- **WHEN** приложение стартует на пустой БД
- **THEN** API отдаёт пустой набор настроек, интерфейс администратора предлагает заполнить их

### Requirement: Шифрование секретов и маскировка

Значения, помеченные секретами, SHALL шифроваться AES-256-GCM ключом `APP_SECRET` при
записи; ответы API SHALL содержать только маскированное представление (`sk-t****xx`),
пометку `isSecret` и источник значения (`settings` / `metrika` / `assigned`).

#### Scenario: Чтение настроек администратором

- **WHEN** администратор открывает страницу «Метрика и данные»
- **THEN** секреты показаны замаскированными, а открытые поля (например `COUNTER_ID`) — как есть

### Requirement: Runtime-запись настроек

`POST /api/settings` SHALL принимать набор значений от администратора, сохранять секреты
в зашифрованном виде и возвращать список изменённых ключей; неавторизованная запись
запрещена.

#### Scenario: Сохранение токена

- **WHEN** администратор сохраняет новый OAuth-токен Метрики
- **THEN** токен шифруется и сохраняется, ответ перечисляет `YANDEX_OAUTH_TOKEN` среди
  изменённых, а последующие синк-запросы используют новое значение

### Requirement: Источники значений

Каждое значение SHALL иметь источник: задано в настройках (`settings`), получено из
Метрики (`metrika`) или назначено (`assigned`); обновление из Метрики не должно терять
ручные значения без причины.

#### Scenario: Обновление из Метрики

- **WHEN** администратор выполняет «Обновить данные из Метрики»
- **THEN** поля, полученные из API Метрики, помечаются источником `metrika`, ручные
  значения остаются с источником `settings`

### Requirement: Токен DataLens

`POST /api/settings/datalens-token` SHALL выпускать персональный токен интеграции
DataLens для авторизованного экспорта CSV.

#### Scenario: Выпуск токена

- **WHEN** администратор запрашивает выпуск токена DataLens
- **THEN** новый токен возвращается один раз при создании и используется экспорт-эндпоинтами
