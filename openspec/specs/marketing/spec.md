# Marketing Weekly Specification

> Открытая спека возможности (OpenSpec). Источник истина — код:
> `code/backend/src/db/migrations/018_marketing_weekly.sql`, `code/backend/src/db/repositories/marketing-repo.ts`,
> `code/backend/src/marketing/{definitions,sheet-data,sync,routes}.ts`,
> `code/frontend/src/routes/marketing.tsx`, `code/shared/src/types/marketing.ts`. Обновлена: 2026-10-27.
> Задача: ANA-73. Источник реальных данных — Google Sheet «Инфопартнеры ProductCamp | лето 2026»,
> лист «стата».

## Purpose

Недельная сетка маркетинга и инфопартнёров — дашборд-замена Google-таблицы «стата»:
13 недель кампании (Август 1–7 … Октябрь 26–01, нерегулярные разбивки сохранены 1-в-1 с
листом) × 13 метрик в двух секциях («Контент-маркетинг», «Инфопартнёры»). Метрики, считаемые
из Метрики/БД, обновляются синком; остальные ячейки аналитик ведёт вручную. У каждого
значения есть источник: `manual` (ручной ввод, синком не перетирается) → `import` (исторический
импорт листа) → `metrika` (пересчёт синка).

## Requirements

### Requirement: Недельная сетка кампании

API SHALL отдавать сетку `GET /api/marketing/weekly`: месяцы, недели (key/start/end/label),
секции, каталог метрик с признаком `sync` и ячейки. Страница `/app/marketing` SHALL рендерить
таблицу в раскладке листа (шапка месяцев с объединением, недели, секции) и быть доступна
авторизованным пользователям.

#### Scenario: Сетка повторяет лист

- **WHEN** открыт `GET /api/marketing/weekly`
- **THEN** возвращаются 4 месяца, 13 недель (например `2026-08-31` покрывает 31.08–06.09),
  2 секции, 13 метрик (9 контент + 4 инфопартнёры), ячейки с источниками

### Requirement: Приоритет источников manual > import > metrika

Массовые записи (синк, импорт) SHALL NOT перетирать ячейки с более высоким приоритетом
источника: синк (`metrika`) пишет только пустые/метрика-ячейки, импорт (`import`) —
пустые/метрика-ячейки. Ручное значение (`manual`) не перезаписывается ничем, кроме явного
`PUT` от пользователя.

#### Scenario: Синк обходит ручную ячейку

- **WHEN** в ячейке `2026-09-07/site_goals` значение с источником `manual`
- **THEN** `POST /api/marketing/weekly/sync` не меняет её; ячейка `2026-09-07/landings_visits`
  при наличии данных `channel_stats` за неделю пишется с источником `metrika`

### Requirement: Ручное редактирование аналитиком

`PUT /api/marketing/weekly` (`{weekStart, metricKey, value, note?}`) SHALL сохранять ячейку с
источником `manual`, автором (из сессии) и временем; аналитик и админ имеют право записи.
Страница SHALL позволять инлайн-редактирование любой ячейки (Enter/уход фокуса — сохранить,
Esc — отмена), показывать в подсказке источник, автора и время правки и подсвечивать источник
цветом. Невалидное значение (не число, отрицательное) не сохраняется.

#### Scenario: Аналитик вводит факт

- **WHEN** аналитик вписывает `120` в ячейку «переходы по ссылкам тг» недели 19–25 и покидает
  поле
- **THEN** ячейка сохранена с источником `manual`, в тултипе — «вручную · email · дата»;
  последующий синк её не меняет

### Requirement: Автосинк считаемых метрик

`POST /api/marketing/weekly/sync` SHALL пересчитывать syncable-строки по данным БД:
`landings_visits`/`site_goals` — суммы `channel_stats` за неделю; `payments` —
`b2c_payments.tickets` + оплаченные `b2b_manual.tickets` (инвариант «заявка ≠ оплата»);
`b2b_leads` — число сделок, добавленных за неделю (`date_added`). Неделя, по которой нет
исходных данных вовсе, SHALL остаться пустой (без обнуления).

#### Scenario: Прошлый период дозагружается

- **WHEN** синк выполняется, а `channel_stats` содержат дни августовских недель
- **THEN** ячейки `landings_visits`/`site_goals` заполнены суммами; недели без данных
  попадают в `skippedWeeks` ответа

### Requirement: Бэкфилл окна из Метрики (только админ)

Синк SHALL быть доступен только администратору (ADMIN_RULES) и SHALL опционально принимать
`from`/`to`: перед пересчётом запускается полный бэкфилл окна через Metrika SyncService
(syncAll), после — пересчёт ячеек. Ответ возвращает счётчики записанных ячеек по метрикам.

#### Scenario: Бэкфилл запускает Метрику

- **WHEN** админ вызывает sync с `from=2026-08-01, to=2026-08-31`
- **THEN** сначала выполняется полный синк окна (runSync), затем пересчёт; аналитик получает
  403 на этот вызов

### Requirement: Импорт реальных данных листа «стата»

Скрипт `pnpm --filter @pca/backend marketing:import` SHALL записывать 112 значений листа
(транскрипция в `marketing/sheet-data.ts`) с источником `import`; повторный запуск обновляет
импортированные ячейки и не трогает `manual`.

#### Scenario: Повторный импорт безопасен

- **WHEN** импорт запущен дважды
- **THEN** второй запуск перезаписывает только `import`/`metrika`-ячейки; `manual` остаются

### Requirement: CSV-экспорт в раскладке листа

`GET /api/marketing/weekly.csv` SHALL отдавать UTF-8 CSV с BOM: колонки «Секция, Метрика» +
по колонке на неделю (с датами), строки — метрики по секциям; пустые ячейки — пустые поля
RFC 4180.

#### Scenario: Файл открывается в таблице

- **WHEN** выгружен CSV
- **THEN** первая строка — «Секция,Метрика,1 неделя (1-7) (2026-08-01..2026-08-07),…», значения
  совпадают с сеткой API
