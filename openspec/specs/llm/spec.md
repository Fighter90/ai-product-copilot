# llm Specification

> Открытая спека возможности (OpenSpec). Источник истины — код:
> `code/backend/src/llm/service.ts`, `code/backend/src/llm/routes.ts`, `code/backend/src/llm/providers/`,
> `code/backend/src/db/migrations/010_auth_settings_ai.sql`, `012_ai_usage_tokens.sql`.
> Обновлена: 2026-10-27.

## Purpose

AI-слой: четыре провайдера (OpenRouter, Anthropic, YandexGPT, GigaChat) с приоритетной
цепочкой и фолбэком. Ключи шифруются AES-256-GCM, каждый вызов пишется в `ai_usage`
(размеры токенов, без контента). Цепочку используют AI-анализ отчёта и RAG-ассистент;
без провайдеров обе функции деградируют штатно.

## Requirements

### Requirement: Реестр провайдеров

Провайдеры SHALL храниться в `ai_providers` (`id`, `enabled`, `priority`, `model`,
`secret_enc`, `extra_json`) и управляться администратором через `/api/admin/ai/providers`;
поддерживаются id `openrouter | anthropic | yandexgpt | gigachat`.

#### Scenario: Просмотр провайдеров

- **WHEN** администратор открывает «AI-провайдеры»
- **THEN** видны четыре карточки с моделью, приоритетом, признаком включённости и
  замаскированным ключом

### Requirement: Цепочка с фолбэком

Запрос `complete` SHALL проходить по доступным провайдерам в порядке приоритета
(`choice='auto'`): сбой или таймаут одного провайдера переключает на следующий; результат
содержит фактических `provider` и `model`.

#### Scenario: Основной провайдер недоступен

- **WHEN** первый по приоритету провайдер отвечает ошибкой
- **THEN** запрос повторяется на следующем доступном провайдере цепочки, и ответ
  помечен его id

### Requirement: Шифрование ключей

Ключи провайдеров SHALL храниться зашифрованными (AES-256-GCM, мастер-ключ `APP_SECRET`);
API SHALL отдавать только маскированные значения, проверка провайдера выполняется
серверным тест-запросом.

#### Scenario: Тест провайдера

- **WHEN** администратор запускает «Проверить» на карточке провайдера с корректным ключом
- **THEN** сервер выполняет пробный запрос и возвращает статус без раскрытия ключа

### Requirement: Учёт использования

Каждый вызов SHALL записываться в `ai_usage` (провайдер, назначение, размеры
input/output токенов, время); контент запросов и ответов SHALL NOT сохраняться.
`GET /api/admin/ai/usage` SHALL возвращать статистику за 30 дней.

#### Scenario: Статистика использования

- **WHEN** администратор открывает статистику AI
- **THEN** видны агрегаты вызовов и токенов за 30 дней без содержимого переписки

### Requirement: Штатная деградация без провайдеров

`GET /api/ai/available` SHALL отражать наличие готовых провайдеров; при их отсутствии
AI-анализ отчёта пропускает нарратив, а RAG-ассистент работает в режиме «только поиск».

#### Scenario: Ни один провайдер не настроен

- **WHEN** снапшот экспортируется, а вопрос задаётся ассистенту
- **THEN** отчёт собирается без AI-разделов, ассистент отвечает найденными фрагментами
  справки, без вызовов LLM
