# Proposal: sync-every-30-min — автосинк Метрики каждые 30 минут + DataLens

> Статус: `approved` (задача пользователя: «Подгружать данные из Яндекс.Метрики должны по
> крону: раз в полчаса… И в DataLens, и в этот проект») · Автор: OpenSpec-сессия · Дата: 2026-10-28
> Связано: ANA-53 (ежедневный автосинк — развиваем), ANA-73 (сетка маркетинга), ANA-60 (DataLens)

## 1. Зачем

Данные в кабинете устаревают до 3 часов (таймер `pca-sync` каждые 3 часа) — для «актуального
дашборда» это долго. DataLens при этом читает CSV-экспорты кабинета: свежесть BI зависит от
свежести базы. Ежедневный автосинк (ANA-53) был первым шагом; теперь частота — 30 минут.

## 2. Что делаем

- Таймер `pca-sync.timer` — каждые 30 минут (окно синка — последние 3 дня: свежие дни +
  экономия квоты; крупные догрузки — вручную через API/CLI).
- После каждого синка автоматически: пересчёт маркетинговой сетки (ANA-73) + запись прогона в
  `sync_runs` (видно в `Админ → Метрика и данные`, `/api/sync/status`).
- Новый юнит `pca-datalens.timer` (каждые 30 минут, сдвиг на 15 минут) — идемпотентное
  обновление воркбука DataLens (`scripts/push-datalens.mjs --workbook=$DATALENS_WORKBOOK_ID`);
  запускается только если `DATALENS_WORKBOOK_ID` задан в `.env` (ConditionEnvironment).
- `deploy.sh`: rsync `scripts/` на сервер + `systemctl restart` таймеров (иначе новое
  расписание не применится без ребута).

**Вне scope:** live-страницы (уже читают Метрику на лету); полноценная пересборка чартов
DataLens чаще, чем раз в 30 минут (тяжело для 1 CPU / 889 MB RAM).

## 3. Критерии приёмки

- [ ] `pca-sync.timer`: `OnCalendar=*:0/30`; после деплоя таймер перезапущен
- [ ] `/api/sync/status` показывает свежий прогон (в течение 30–60 мин после деплоя)
- [ ] Маркетинговая сетка обновляется синком без ручных действий (metrika-ячейки)
- [ ] `pca-datalens.timer` установлен; при незаданном `DATALENS_WORKBOOK_ID` — пропускается
- [ ] Юниты и cli-sync покрыты тестами/гейтами; CI зелёный

## 4. Влияние и риски

- **Квота Метрики:** 48 синков/день × окно 3 дня — с паузингом `METRIKA_REQUEST_DELAY_MS` и
  низким приоритетом (Nice=10) укладывается; при упоре — синк восстановит окно.
- **RAM:** оба юнита ограничены (350M/250M), IOSchedulingClass=idle.
- **Альтернатива:** вебхуки из Метрики (нет у заказчика доступа) — отклонено.
