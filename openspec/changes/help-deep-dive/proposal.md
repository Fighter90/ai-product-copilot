# Proposal: help-deep-dive — справка, разжёванная до мелочей

> Статус: `approved` (задача пользователя: «максимально дигитализируй раздел справки, чтобы всё было разжевано до мелочей») · Автор: OpenSpec-сессия · Дата: 2026-10-27
> Связано: ANA-71 (лендинг), ANA-63/64 (документация ролей/интеграций), ANA-73 (страница «Маркетинг»)

## 1. Зачем (проблема и контекст)

Справка (`docs/help/{ru,en}/`, 20 статей × 2 языка, ~1830 строк) отстаёт от продукта:

1. **Нет статьи о странице «Маркетинг и инфопартнёры»** (ANA-73, релиз v3.2.0) — новый
   функционал с нетривиальной моделью источников (manual > import > metrika) не документирован.
2. **Тонкие статьи**: 8 из 20 статей — 61–63 строки; описывают «что нажать», но не «что это
   значит»: ни формул, ни ограничений, ни источников данных, ни типичных ошибок.
3. **Нет глоссария** — термины («заявка ≠ оплата», goal_reaches, sync window, ICE, KPI-gap,
   приоритеты источников) разбросаны по статьям и справочнику терминов `@pca/shared/terms.ts`,
   но в справке не собраны.
4. **Нет формул** — аналитик не видит, как считаются CR, «Оплачено», gap, прогноз достижения
   цели, недельные агрегаты маркетинговой сетки.
5. **Нет troubleshooting** — частые ситуации (пустые графики после синка, 429/квота Метрики,
   разлогин при 5xx, 504 AI-анализа, разрывы в b2b/b2c-данных) не описаны.

## 2. Что делаем (цель)

Справка покрывает **каждый экран, каждую метрику, каждый термин и каждую типичную проблему**
настолько подробно, чтобы новый аналитик работал без консультаций: 4 новые статьи RU+EN
(«Маркетинг и инфопартнёры», «Глоссарий», «Формулы и расчёты», «Если что-то не работает»),
глубокая доработка 8 тонких статей (каждый блок UI, каждая цифра, ограничения и источники),
ссылки из справки на проверочные скрипты. EN — полный паритет.

**Вне scope:** изменение кода справочной подсистемы (help.ts, поиск, чанки — не трогаем),
скриншоты (существующие остаются, новые делаются скриптом по мере надобности), перевод
документации вне `docs/help/`.

## 3. Критерии приёмки (измеримые)

- [ ] 24 статьи × 2 языка (было 20) — паритет имён файлов и порядка (order) сохранён
- [ ] Новая статья «Маркетинг и инфопартнёры» описывает: сетку недель, 13 метрик, источники
      значений (manual > import > metrika), ручное редактирование, синк/бэкфилл, CSV-экспорт
- [ ] Глоссарий ≥ 25 терминов; каждая формула (CR, «Оплачено», gap, прогноз, ICE, недельные
      суммы) выведена и объяснена с примером
- [ ] Troubleshooting ≥ 12 ситуаций «симптом → причина → что делать»
- [ ] Каждая тонкая статья (было 61–63 строки) расширена ≥ 2×, с разбором каждого блока UI
- [ ] EN-версии — полный паритет, без кириллицы (проверка существующими тестами)
- [ ] Все тесты зелёные: backend help.test/help-relevance, frontend HelpCenter, i18n-аудит
- [ ] Спека возможности: `openspec/specs/help/spec.md`

## 4. Влияние

- **Контент:** `docs/help/ru/*.md`, `docs/help/en/*.md` (4 новых + 8 расширенных).
- **Код (точечно):** `src/components/PageHelpLink.tsx` — слаг `marketing` + маршрут
  `/app/marketing` (ссылка «?» со страницы маркетинга).
- **API/БД/зависимости:** не затрагиваются.

## 5. Риски и альтернативы

- **Риски:** устаревание цифр (формулы привязаны к коду — в спеке указаны файлы-источники);
  длинные статьи тяжелее читаются — лечится оглавлением (h2/h3 уже рендерится) и
  «короткий ответ → детали».
- **Альтернативы:** генерировать справку из кода (сложно, отклонено); оставить как есть
  (отклонено пользователем).
