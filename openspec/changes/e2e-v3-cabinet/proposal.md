# Proposal: e2e-v3-cabinet — E2E-сьют переводится на кабинет v3 (авторизация, роуты /app/*, webkit)

> Статус: `approved` (утверждено в чате: «упавшие тесты E2E — проверь» + переход на SDD/OpenSpec) · Автор: OpenSpec-сессия · Дата: 2026-10-27
> Связано: ANA-66 (регресс прода), ANA-71, release v3.2.0 · Затрагивает: `e2e/*`, `.github/workflows/e2e.yml`

## 1. Зачем (проблема и контекст)

Локальный прогон и CI (`E2E`, run 40542158797) падают — **21 тест из 69**. Две независимые причины:

1. **Мобильный проект Playwright ходит в WebKit, а он не установлен.** `devices['iPhone 14']`
   несёт `defaultBrowserType: 'webkit'`; локально webkit не скачан, в CI
   (`pnpm exec playwright install --with-deps chromium`) ставится только chromium → все 10
   тестов `mobile.spec.ts` падают с «Executable doesn't exist» / таймаутами.
2. **Пять спек писаны под v2-приложение** (публичные маршруты без авторизации), тогда как v3 —
   кабинет с входом (`/login` → `/app/*`, `RequireAuth`):

   | Спека             | v2-ожидание                                                          | Реальность v3                                                                                                          |
   | ----------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
   | `smoke.spec.ts`   | `/` — дашборд; ссылка «Настройки»; кнопка «Сформировать срез данных» | `/` — публичный лендинг; настройки — `/app/admin/metrika` («Метрика и данные»); кнопка — «Собрать отчёт» (`rep.build`) |
   | `filters.spec.ts` | фильтр на `/`, `header span.font-mono`                               | кабинет за логином; FilterBar на `/app`; пресеты `flt.presetDays`                                                      |
   | `report.spec.ts`  | `/report`, «Сформировать срез данных»                                | `/app/report`, «Собрать отчёт» (ANA-39: одна главная кнопка)                                                           |
   | `b2b.spec.ts`     | «B2B lives in Settings», `/b2b → /settings`                          | `/b2b` → `/app/b2b` (страница «B2B-сделки»)                                                                            |
   | `mobile.spec.ts`  | пути `/`, `/traffic`, … `/settings`                                  | `/app`, `/app/traffic`, … `/app/admin/metrika`                                                                         |

   Уже переведены на v3 и зелёные: `dashboard-pages`, `roles`, `overview-fold`, `a11y`,
   `contrast` (мокают `/api/auth/me`, localStorage `pca.onboarded`).

Дополнительно при локальном прогоне падают 4 теста, зелёные в CI (`dashboard-pages` — воронка,
`hypotheses` — канбан/дип-линк/решения): в `installMocks` нет заглушек новых эндпоинтов,
которые страницы v3 дергают на монте (`/api/payments/summary`, `/api/payments/b2c`,
`/api/sync/status`, `/api/demo/status`, `/api/marketing/weekly`), — catch-all `'[]'` в части
спек возвращает массив там, где страница ждёт объект, и рендер падает до проверяемых маркеров.

## 2. Что делаем (цель)

E2E-сьют снова детерминированно зелёный локально и в CI и описывает **кабинет v3**:
общая фикстура авторизации и серверных заглушек, переписанные 5 спек под роуты и тексты v3,
установка всех нужных браузеров в CI. Сьют продолжает мокать сеть на уровне Playwright —
без OAuth-токена и реального бэкенда. **Вне scope:** изменение продуктового кода фронтенда,
реальные сквозные тесты против прода (это `scripts/e2e-prod-check.mjs`).

## 3. Критерии приёмки (измеримые)

- [ ] `pnpm e2e` локально: **0 failed** (все спеки, оба проекта chromium + mobile-iphone-14).
- [ ] CI `E2E` на ветке зелёный; в workflow ставятся все используемые браузеры
      (`chromium webkit`).
- [ ] Ни одна спека не ссылается на v2-маршруты/тексты: `/settings`, «Сформировать срез
      данных», «B2B-пайплайн (ручной ввод сделок)» — grep по `e2e/` не находит.
- [ ] `installMocks` покрывает: `/api/auth/me` (роль — параметр), `/api/notifications`,
      `/api/demo/status`, `/api/sync/status`, `/api/payments/summary`, `/api/payments/b2c`,
      `/api/marketing/weekly`, `/api/help/*` — страницы кабинета не падают на монте.
- [ ] Инвариант «заявка ≠ оплата» проверяется e2e на `/app/funnel` (текст `an.fn.b2bPaid`).
- [ ] Спека возможности `openspec/specs/e2e/spec.md` описывает итоговый сьют.

## 4. Влияние

- **Код:** только `e2e/*.spec.ts`, `e2e/fixtures.ts`, `.github/workflows/e2e.yml`.
- **Продуктовый код:** не меняется. **Данные/БД/API:** не затрагиваются.
- **Документация:** `openspec/specs/e2e/spec.md` (новая), CHANGELOG (раздел 3.2.0 уже упоминает
  e2e — дополнить при необходимости).

## 5. Риски и альтернативы

- **Риски:** моки отстают от новых страниц (лечится catch-all + точечными заглушками в
  фикстуре); webkit-специфика рендера (шрифт-метрики) — mobile-тесты проверяют только
  отсутствие горизонтального скролла, не пиксели.
- **Альтернативы:** выкинуть mobile-проект (теряем покрытие 390px — отклонено, ANA-48);
  перейти на реальные API-вызовы с сид-данными (медленно, нужен OAuth — против подхода сьюта).
