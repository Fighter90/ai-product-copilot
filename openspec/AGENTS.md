# OpenSpec — правила для AI-агентов

Кратко: **перед фичей — proposal, после — specs.**

1. **Перед реализацией нетривиальной фичи** (затрагивает > 1 файла / > ~30 минут; меняет модель
   данных, API, методологию или KPI-математику): создай `openspec/changes/<id>/proposal.md` по
   шаблону [`changes/_template/proposal.md`](changes/_template/proposal.md) — зачем, что, критерии
   приёмки, влияние, риски. Получи утверждение от человека **до** написания кода.
2. **После утверждения**: скопируй `changes/_template/tasks.md` в `changes/<id>/tasks.md`,
   распиши TDD-шаги (тест → код), реализуй по чек-листу.
3. **После реализации и влития**: перенеси итоговое поведение (не историю работ) в
   `openspec/specs/<capability>/spec.md` — создай или обнови спеку возможности. Папку изменения
   удали или пометь архивной.
4. Опечатки, разовые правки, чистка, зависимости, документация — без proposal'а.
5. Вечные спеки описывают **текущее состояние системы**; расхождения с кодом фиксируются
   обновлением спеки, а не молчанием. Исторические спеки: `docs/specs/` (см. его README).
