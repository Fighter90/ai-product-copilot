## [3.4.1] - 2026-11-05

### Fixed

- **Live-страницы переживают любой сбой Метрики (stale-on-error).** TtlCache отдаёт последний
  хороший ответ с флагом `stale: true` при 429/400/сети — страница рендерит данные + баннер
  «последние доступные данные» вместо ошибки. Без кэша — человекочитаемый 503 `METRIKA_*`
  (квота / слишком широкий интервал / недоступен) вместо сырого «Bad Request».
- **400 «Запрос слишком сложный» устранён в корне:** live-запросы clamp-ятся до 31 дня
  (Metrika отклоняла goal-breakdown за весь период: 10–26 с сервера и 400). В payload —
  `rangeClamped`/`effectiveFrom`; полная история за любой период — в разделах из БД,
  которые живут на SQLite и от Метрики не зависят.
- **Финальная per-таблицная сверка — OVERALL PASS (ANA-65/109).** `reconcile --tables-only`
  переписан на широкие 31-дневные окна с `ym:s:date`-ячейками (ANA-113-стиль, ~72 вызова вместо
  2253): однодневные breakdown-срезы попадали под k-anonymity row-hiding Метрики (редкие ключи
  скрыты — DB 171 визит против 8) и давали ложные MISMATCH. Полный порт `normalizePageUrl`
  (бакет `/tilda/*` для виртуальных событий Tilda), `limit: 10_000` (rangeLimit, как в синке),
  два документированных механизма-объяснения: legacy utm_stats (до Nov 2026 хранила только
  размеченный трафик) и post-sync refinalisation drift (Метрика доуточняет поздние сессии,
  Δ ≤ max(8, 5 %), guards: нет DB-only ключей и value-диффов).
- **UI:** «Опасная зона» — последняя карточка админ-страницы «Метрика и данные» (после
  резервного аккаунта): деструктивное действие не попадается на глаза при работе с настройками
  (`MetrikaDangerZone` выделен в отдельный компонент); блоки страницы смонтированы в единый
  `space-y-6` — одинаковые вертикальные отступы.
- **Self-heal после деплоя:** открытая вкладка не могла догрузить lazy-чанки прошлого билда
  («Failed to fetch dynamically imported module», «Не удалось загрузить раздел») — на
  `vite:preloadError` страница перезагружается один раз за сессию и забирает новый
  `index.html` (`lib/preload-recovery.ts`, +3 теста).
- **deps:** pnpm overrides — `glob >=14.0.2`, `minimatch >=11.0.1` (2 moderate advisory;
  адресные — minimatch@3.1.5 у eslint не затронут), `pnpm audit` — 0 known vulnerabilities.
- **CI:** `QA/**` (разовые verify-скрипты) исключён из eslint; e2e-воркфлоу — manual-only
  (бейдж обновлён успешным ручным прогоном).
